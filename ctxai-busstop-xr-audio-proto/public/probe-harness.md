# 🎧 프로브 하네스 — 다섯 사건을 실제로 겪게 하고, 반응을 기록한다

**작성:** 개발(세션) · 2026-08-22
**주소:** `/probe` (헤드폰 필수)
**근거:** `정류장_스크립트_v2.md` §1·§2 · `판정_기준.md` · `구현_리스크와_지원_필요사항.md` §1-1

## 0. 왜 만들었나 — 자극이 없으면 반응도 없다

판정 로직 전체가 **"다섯 사건에 대한 반응"**을 전제로 짜여 있습니다. 행동 채널에 50% 가중치를 주는 근거도 `판정_기준.md` §3 의 *"5개 사건 다각도 관찰이라 근거가 제일 두꺼움"* 입니다.

그런데 **그 다섯 사건이 존재하지 않았습니다.** `/judge-v2` 가 실제로 재던 것은 *"카메라 앞에서 11초 동안 아무 자극 없이 뭘 했는가"* 였습니다. `judgeFromBehavior()` 가 찾는 신호 — 방어 반응, 지속 경계, 느린 회복, 방향 전환 — 는 전부 **자극이 있어야 생기는 것**이라, 임계값을 아무리 튜닝해도 파일럿 자체가 성립하지 않았습니다.

`구현_리스크와_지원_필요사항.md` §1-1 이 적어 둔 상태가 이것의 증상입니다:

> *"마지막 라운드에서는 회귀 테스트 4개 중 2개가 재실패해서, 패치가 패치를 부르는 상태였습니다."*

## 1. 하네스가 하는 세 가지

| | 무엇 | 푸는 문제 |
|---|---|---|
| ① **자극 제시** | 다섯 프로브를 정확한 시점·방위로 (HRTF 공간음향 + 최소 시각 큐) | *자극이 없어서 반응도 없다* |
| ② **기록** | 요각·랜드마크·표정·오디오를 원시 시계열로 저장 | *검증할 데이터셋이 없다* (§1-1) |
| ③ **리플레이** | 저장된 세션을 판정 함수에 다시 통과시켜 대조 | *패치가 패치를 부른다* |

**셋이 같은 물건입니다.** 그리고 이것이 아래 §5 논문 프레이밍의 실험 장치이기도 합니다.

## 2. 무엇을 겪게 되나

`/probe` 에서 **헤드폰을 끼고 마우스를 끌면** 벤치에 앉은 채로 고개를 돌립니다. 이동은 없습니다.

```
0 ~ 8초    기저선 — 자극 없음. 이 구간의 평균 자세가 이후 모든 이탈의 기준점
10초       찢어진 포스터   오른쪽 72° 근거리      시각 + 파닥
22초       카페 문·우비 인물 왼쪽 -38°→-14°, 52m→26m  청각(딸랑) + 이동
40초       포터 트럭 물보라  오른쪽 78° → 왼쪽 -78°   시청각
49초       개구리          등 뒤 오른쪽 135°       ★ 소리만
58초       고양이          오른쪽 70° → 왼쪽 -80°   시청각
65초       두 번째 울음     왼쪽 시야 밖 -115°       ★ 소리만
71 ~ 76초  꼬리 구간 — "사건이 끝난 뒤에도 그 방향을 의식하는가"(재확인)를 잰다
그 뒤       Q1 "당신은 무엇을 기다리고 있습니까?" → 답하거나 안 하거나 → 설문
```

**개구리와 두 번째 울음은 소리만 있고 화면에 아무것도 없습니다.** 그게 그 프로브의 설계입니다 — *"무슨 일이 있었는지는 보여주지 않는다"* (v2.md §1-5).

3D 는 전부 코드로 만든 판자 수준입니다. 아트 GLB 는 아직 없고, 하네스의 목적은 형태의 완성도가 아니라 **방향·시점·거리**입니다. GLB 가 나오면 `components/ProbeStage.jsx` 의 도형만 교체하면 됩니다 — 배치 좌표는 `/whitebox` 와 같은 규약(원점 = 벤치 착석 지점 바닥, 눈높이 1.15m)을 씁니다.

## 3. 판정 신호를 요각으로 바꿨습니다 (방식 B)

`v2.md` §5 가 확정한 시선의 정의는 **"헤드셋 헤드 포즈(머리 위치·회전) 기준"** 입니다. 마우스 룩의 **요각(yaw)이 바로 그 물리량**이고, 지금까지 쓰던 웹캠 코끝 좌표 편차는 그것의 조잡한 근사였습니다.

| | 이전 (웹캠 코끝 좌표) | 지금 (마우스 요각) |
|---|---|---|
| 무엇을 재나 | 얼굴 중심 대비 코의 치우침 | 시선 방향(도) 그 자체 |
| 임계값 근거 | 제 임의값 | 물리량 직접 측정 |
| 개구리 135° | ⚠️ **얼굴 인식이 끊김** (정면 카메라 사각지대) | ✅ 그냥 측정됨 |
| 헤드셋 전환 | 신호가 달라짐 | 소스만 마우스 → IMU 로 교체 |

**웹캠은 계속 씁니다** — 표정 모델(블렌드셰이프) 채널은 웹캠에서만 나오고, 이건 셋 중 근거가 가장 두꺼운 신호입니다.

**두 신호를 나란히 기록합니다.** 판정은 요각으로 하되 코끝 좌표도 같은 세션에 남깁니다. 나중에 *"코끝 좌표 휴리스틱이 요각을 얼마나 잘 근사했나"* 를 실제로 측정할 수 있고, 그 자체가 결과가 됩니다 — 헤드셋 없이 웹캠만 쓰는 전시 구성이 가능한지에 대한 근거이기도 합니다.

### 남은 한계 — 절대 임계값은 전이되지 않습니다

고개를 실제로 135° 돌리는 건 몸의 결단이지만 마우스를 끄는 건 공짜입니다.

| 전이됨 ✅ | 전이 안 됨 ❌ |
|---|---|
| 잠복기 · 체류 시간 · 복귀 시상수 · 재확인 횟수 · 프로브 간 상대 순위 | 회전 진폭 절대값 · "몸을 뒤로 뺌"(마우스엔 없는 동작) |

데스크톱 하네스의 역할은 **"임계값 확정"이 아니라 "프로브가 애초에 서로 다른 반응을 유발하는가"의 검증 + 회귀 픽스처 확보 + 파이프라인 완성**입니다. 최종 캘리브레이션은 실제 장비에서 다시 합니다.

## 4. 구조

### 파일

```
lib/probes.js         프로브 배터리 정의 (시점·방위·고도·양식·반응창) · 순수
lib/spatialAudio.js   HRTF 공간음향 + ★리스너 방향 갱신 + 프로브 음색 합성
lib/behaviorCore.js   ★신규 — 판정 계산만. 브라우저 API 를 안 쓴다 (node 에서 돈다)
lib/behaviorSense.js  웹캠 입력(sampleFrames) + behaviorCore 재수출
lib/probeWindow.js    프로브별 반응 커널 + f(R) · 순수
lib/sessionRecord.js  JSONL 기록 · gzip · 업로드
components/ProbeStage.jsx  1인칭 화이트박스 + 마우스 룩 + 시각 큐
app/probe/page.jsx    게이트 → 진행 → Q1 → 설문 → 저장
app/api/session/      세션 저장·목록·원본 서빙
scripts/synth-sessions.mjs  합성 세션 생성 (픽스처)
scripts/replay.mjs    리플레이 + 골든 대조
fixtures/             회귀 픽스처 7개 (gzip, 총 128KB)
```

### 핵심 리팩터 — I/O 와 계산의 분리

```
[라이브]   카메라 → sampleFrames → RawSample[] ─┐
                                                ├→ metricsFrom → judge → fuse
[리플레이] JSONL  →   파일 읽기  → RawSample[] ─┘
```

`RawSample[]` 이 공통 경계면이라 **라이브와 리플레이가 같은 결과를 낸다는 게 구조적으로 보장**됩니다. MediaPipe 는 브라우저 전용이라 node 에서 영상→랜드마크를 다시 못 뽑으므로, 경계면을 랜드마크에 잡았습니다.

### ★ 급소 — 리스너 방향 갱신

`lib/audio.js` 는 소리의 위치만 설정하고 **듣는 사람이 어디를 보고 있는지는 갱신하지 않았습니다.** 둘러보는 기능이 없어서 문제가 안 됐던 것입니다.

이게 없으면 **마우스로 개구리 쪽을 봐도 소리가 계속 오른쪽 뒤에서 들립니다.** 관객은 "찾았다"는 확인을 못 받고 프로브 전체가 성립하지 않습니다. 세 줄짜리 일이지만 하네스의 급소입니다.

### 세션 형식

```jsonc
{"type":"meta",  "sessionId":"s_…","probeSet":"v2.6probes.2026-08-22","judgeSignal":"yaw","consent":true}
{"type":"probe", "id":"frog","onsetMs":49000,"windowMs":6000,"azimuth":135,"radius":2.6,"modality":"a"}
{"type":"gaze",  "t":49183,"yaw":47.28,"pitch":-2.1}          ← 60fps · 판정 주 신호
{"type":"frame", "t":49200,"lm":[…129개…],"bs":{…},"vis":0.94} ← 웹캠 15fps
{"type":"channels","textScores":{…},"voiceScores":null,"transcript":"…"}
{"type":"label", "selfReport":"H","immersion":4,"noticed":"no","free":"…"}
```

- **랜드마크는 43개 점**을 저장합니다. 지금 계산에 쓰는 5개만 저장하면 나중에 기준점을 바꿀 때 과거 데이터를 못 씁니다 — 실제로 이미 한 번 바꿨습니다(턱 152 → 미간 168, 손 가림 대응).
- **원본 영상은 저장하지 않습니다.** 랜드마크만 남기면 개인식별성이 훨씬 낮아 동의 절차가 가벼워지고, 판정에 필요한 것도 랜드마크뿐입니다. (동의서는 요청서 v5.0 §3.3 의 8/15 항목)
- 세션 원본 ~950KB → **gzip 30KB**. Vercel 함수의 요청 바디 상한(~4.5MB)에 여유가 큽니다.

## 5. 이게 논문이 되는 지점 — 서사를 계측기로 쓴다

> **「서사를 계측기로: 디제틱 프로브를 이용한 무요구 관객 상태의 자극 동기화 추정」**
> *Diegetic Probes: Stimulus-Locked Estimation of Non-Elicited Audience State*

감정 인식 연구는 거의 전부 **유도된(elicited) 반응**을 씁니다 — 자극 영상을 보여주고 재거나, 연기한 표정 데이터셋을 쓰거나, "지금 기분을 말해 주세요"라고 묻습니다. 이 작품은 그걸 하면 안 됩니다 (v1.1 §2 *"관객이 해야 할 일은 벤치에 앉아 버스를 기다리는 것뿐"*).

이 제약을 정면으로 받으면 문제가 다른 문제로 바뀝니다.

```
[기존]  자유로운 상태의 얼굴 → 감정 라벨        ← 포화됐고, 로맨스는 애초에 안 됨
[바뀐]  알려진 시각·방위의 자극 → 반응 커널     ← 유발전위(ERP) 패러다임과 같은 구조
```

```
프로브 배터리   P = {p₁ … p₆},  pᵢ = (tᵢ, θᵢ, φᵢ, mᵢ, τᵢ)
반응 커널       rᵢ = Φ( S[tᵢ, tᵢ+τᵢ] )
반응 프로파일   R = [r₁ … r₆]
장르 친화도     g = f(R) ∈ Δ²
미디어 라우팅   연속 채널 → 보간 · 이산 채널 → 최근접 매칭 · 생성 채널 → 제약 조건부 생성
```

**이 프레이밍이 실제로 푸는 것:**

1. **로맨스가 에크만 기본감정에 없는 문제** (`구현_리스크` §1-3) — 로맨스를 감정이 아니라 **반응 프로파일**로 정의하면 됩니다. `R = 1 - max(H,C)` 라는 잔여값을 버리고 *"사람 프로브 지속 추적 + 낮은 각성"*이라는 측정값이 됩니다. 코드에 이미 반영돼 있습니다.
2. **라벨 없는 데이터** — 세션 100개가 자유 발화 100개가 아니라 **600개의 자극-반응 쌍**이 됩니다.
3. **복제 불가능성** — 프로브 배터리는 서사와 함께 설계돼야 작동합니다. 개구리를 등 뒤 135°에 둔 것은 정면 카메라 사각지대를 이용한 계측 결정인 동시에 *"놀래키려는 게 아니라 생물에 대한 반응을 보려는"* 연출 결정입니다. 둘이 분리되지 않습니다.

**검증 설계** (심사에서 반드시 물어볼 것)

| 질문 | 실험 |
|---|---|
| f(R) 이 예측력이 있나 | 자기보고 대비 상관, 랜덤/최빈값 기저선 대비 |
| 프로브가 실제로 기여하나 | **절제 실험** — 프로브를 하나씩 빼고 예측력 하락 측정 (논문의 중심 그래프) |
| 재현되나 | 같은 참가자 재측정 시 프로파일 일치도 |
| 관객이 눈치채나 | 사후 설문 *"측정당한다고 느꼈습니까"* ← **무요구 조건의 핵심 검증. 설문 3번 문항이 이것** |
| 자기보고가 정답인가 | ⚠️ 제일 약한 고리. **몰입도·만족도를 종속변수로 쓰는 게 방어하기 쉽습니다** — 설문 2번 문항 |

## 7. 만들면서 실제로 잡은 결함 다섯 가지

하네스를 만드는 과정 자체가 판정 로직의 버그를 잡았습니다. 전부 합성 세션이 없었으면 못 봤을 것들입니다.

1. **지나가는 자극을 "쳐다본 것"으로 집계** — 가만히 있는 관객도 시야를 가로지르는 프로브(트럭 78°→-78°, 고양이 70°→-80°)를 획득으로 잡았습니다. 자극이 관객의 정지 시선과 한 번 일치하기 때문입니다. **자극이 지나간 것은 반응이 아닙니다.** → 최소 회전량(8°) 요구로 수정.
2. **가만히 있으면 코미디 점수가 붙음** — `recoveryMs = 0` 일 때 `fastRecoverySig = 1.0` 이 돼서, 전혀 움직이지 않은 관객이 자동으로 C 를 0.33 받았습니다. → `moved` 플래그로 게이트.
3. **표정 점수가 좌표 튐 때문에 버려짐** — 손이 얼굴을 스쳐 좌표가 튀면 그 프레임의 **표정 모델 출력까지** 같이 버려졌습니다. 근거가 가장 두꺼운 채널을 가장 약한 채널 때문에 버리는 셈이라 방향이 거꾸로였습니다. → 표정은 얼굴이 잡힌 모든 프레임에서 측정.
4. **우비 인물을 보는 것이 "지속 경계"(공포)로 계산됨** — `v2.md` §2-4 A-2 는 *"**사라진** 우비 인물"*을 재확인하는 것을 경계라고 합니다. 보이는 동안 보는 것은 §2-4 C 의 *"우비 인물엔 관심을 보임"*, 즉 로맨스입니다. → 체류(dwell)와 재확인(revisit)을 분리.
5. **`sustainedSec` 이 프레임률에 의존** — 프레임 간격을 30fps 로 가정하고 있어서, 실제 프레임률이 다르면 값이 통째로 틀어졌습니다. → 실제 타임스탬프 차이로 계산.

그리고 죽어 있던 코드 두 개를 살렸습니다: `smoothScores()`(정의만 되고 호출 없음), `minVisibility()`(계산해 놓고 안 씀 → 세션에 기록).
