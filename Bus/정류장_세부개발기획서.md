## 1. 먼저 — 컨셉 문서에서 발견한 구멍 4개

세부 명세로 옮기는 과정에서, 컨셉 단계에서는 보이지 않던 **실제로 막히는 지점** 네 개가 드러났습니다. 나머지 장을 읽기 전에 이것부터 봐 주세요.

### 🔴 구멍 1 — 명사 콜백과 사전 녹음이 서로 모순됩니다

컨셉 문서 7장은 **"대사는 미리 만들어 두고 음성도 미리 합성해 파일로 보관"**한다고 정했습니다.
그런데 4장 「장치 셋」은 **"관객이 말한 명사를 빈칸에 넣어 되돌려준다"**고 합니다.

관객이 무슨 명사를 말할지는 체험 당일에야 알 수 있습니다. **미리 합성한 음성 파일에는 빈칸을 넣을 수 없습니다.**

이 장치는 문서 스스로 *"장르를 섞는 것보다 이쪽이 먼저 작동한다"*고 평가한 핵심 장치입니다.

**해결: 지연 문제가 아닙니다.** 명사는 1분 40초에, 콜백은 6분 50초에 발생합니다 — 사이에 5분 10초가 비어 있습니다. 문장 전체를 런타임에 합성해 **미리 구워 두면** 됩니다. 추가 에셋 16개, 명사 목록 불필요. 상세는 §8.

### 🔴 구멍 2 — 12벌인가 16벌인가가 문서 안에서 엇갈립니다

| 위치 | 표기 |
|---|---|
| 4장 「태도는 두 층」 | 문장 층 **16벌** 필요 |
| 4장 「몇 가지가 나오나」 | 사건 4 × 태도 4 = **16가지** |
| 8장 역할 분담 | 대사 **12벌** |
| 10장 경로 (9~10월) | 대사 **12벌** |
| 13장 착수 목록 | 대사 **12벌** |

**16이 맞습니다.** 혼합 12 + 순수 강화 4 = 16. 순수 배합(사건=태도)도 고유한 문장 층이 필요합니다 — "나를 알아보면서 동시에 로맨스의 어법으로 말하는" 대사는 혼합 12벌 어디에도 없습니다.

📐 **이 문서는 전부 16으로 통일합니다.** 8·10·13장의 "12벌"은 16벌로 수정이 필요합니다. 작업량은 16 × 3.5줄 ≒ **56줄**.

### 🔴 구멍 3 — lightmap 2장 크로스페이드가 도구 선택을 결정합니다

컨셉 문서 5장은 색을 계산하지 않고 **"조명 프리셋 두 장을 가중치대로 크로스페이드"**한다고 정했습니다. 이것을 구현하려면 셰이더에서 `mix(lightmapA, lightmapB, t)`를 해야 합니다. 표준 머티리얼은 lightmap 슬롯이 **한 개**뿐입니다.

- **A-Frame** — lightmap 슬롯이 하나. 두 장 블렌딩은 three.js 셰이더를 직접 작성해야 함 → 문서가 A-Frame을 고른 이유("아트가 직접")가 이 지점에서 무너집니다
- **PlayCanvas** — 에디터에서 셰이더 chunk 교체 지원. 아트는 프리셋을 슬롯에 넣고, 개발자는 chunk를 한 번만 작성

📐 **PlayCanvas를 권합니다.** 근거는 2장.

### 🔴 구멍 4 — 위험은 역할 중복이 아니라 일정 여유가 0이라는 것입니다

8장 역할 분담에서 **AI·데이터**와 **개발** 모두 정동욱 1인입니다.

**한 사람이 양쪽을 다 하는 것 자체는 문제가 아니고, 오히려 유리합니다.** 이 프로젝트에서 진짜 어려운 부분은 마이크 → 서버 → 빛·소리로 이어지는 **이음새**입니다. 양쪽을 한 사람이 쥐고 있으면 API 협상 비용이 0입니다. 나누면 필드 이름 왕복이 오히려 며칠을 먹고, 팀 나머지 3명은 아트·기획·사운드이므로 나누자는 건 19일 안에 사람을 가르치자는 뜻입니다. 컨셉 6장이 브라우저를 고른 이유도 원래 이것이었습니다 — 이제 JS + Python, 둘 다 익숙한 언어입니다.

**실제 위험은 총량입니다.** 백엔드 5일 + 프론트 8일 + 검증·실험·리허설 5일 = 18일. D-19에 여유가 하루뿐이고 의존 사슬이 한 줄입니다. 이건 **나눠서 해결되지 않고, 잘라서 해결됩니다.**

📐 완화안 (13·14장 일정에 반영):

1. **가장 비싼 항목을 잘라낼 기준을 지금 정해 둡니다.** 시연 7항목 중 비용이 가장 큰 것은 5번(빛·안개)이고 — PlayCanvas 씬 + lightmap 셰이더로 8/12~8/13 이틀 — **컨셉 3장이 직접 "조명만 달랐다는 평가는 실패"라고 말한 항목**입니다. 즉 가장 비싼 것이 실험 성패를 결정하지 않습니다. **8/13 종료 시점에 셰이더가 안 되면 버리고 안개 색·농도 보간만으로 갑니다** (반나절). 미리 정해 두면 그날 사흘을 더 쏟지 않습니다.
2. **여기서 아낀 시간은 6번(NPC 대사)으로 돌립니다.** 사건당 1줄 → 3줄. *"나는 붙잡았는데"*를 만드는 유일한 항목이 이것입니다.
3. **개발자가 필요 없는 일을 8/4에 전부 넘깁니다.** TTS 배치 합성, `manifest.json` 편집, 사운드 루프, PlayCanvas 씬 조립. 스키마와 도구만 던져주면 아트·기획팀이 개발자를 기다리지 않고 굴러갑니다. **실질적인 유일한 병렬화입니다.**
4. 백엔드를 먼저 완성해 `curl`로 검증 가능한 상태로 고정 (8/4~8/8). 프론트 오디오 믹서는 3D 없이 HTML 한 장으로 먼저 검증 (8/9~8/11).

🔴 **남는 위험 하나:** 8/20에 담당자가 아프면 아무것도 나오지 않습니다. 4인 팀에서는 피할 수 없으니, `main`을 항상 시연 가능 상태로 유지하고 **"서버 켜는 방법" 한 장을 8/17에 미리 써 두는** 것으로 덮습니다.

## 2. 기술 스택 확정

### 🔧 프론트엔드

| 항목 | 선택 | 근거 |
|---|---|---|
| 런타임 | **PlayCanvas** (WebXR) | lightmap 2장 블렌딩을 에디터 워크플로 안에서 처리 가능 (§1 구멍 3). 아트가 브라우저에서 직접 조명·배치 편집 |
| 오디오 | **Web Audio API** 직접 사용 | PlayCanvas 사운드 컴포넌트를 쓰지 않음. 4-stem 등가전력 믹싱을 직접 제어해야 함 (§7.2) |
| 마이크 | `getUserMedia` + `MediaRecorder` (audio/webm;codecs=opus) | Quest 3 브라우저 지원 확인 필요 (8/17 실기 검증 항목) |
| 준언어 분석 | `AnalyserNode` + 자체 스크립트 (클라이언트 계산) | 오디오를 서버로 보내 분석하면 왕복이 2번. RMS·F0·침묵은 클라이언트에서 계산해 숫자만 전송 |
| VR 진입 | WebXR `immersive-vr` + PC 폴백 | 주소 하나로 프로젝터/헤드셋 양쪽 (컨셉 6장) |
| 타깃 | Quest 3 브라우저, 72fps | |

> **A-Frame을 고르는 경우:** 조명 전환을 lightmap 블렌딩 대신 **실시간 조명 3개 + fog 색 보간**만으로 구현한다는 조건에서만 성립합니다. 이 경우 "구운 빛의 질감"을 포기하는 대신 셰이더 작성이 사라집니다. 8/5까지 아트팀과 함께 30분 테스트로 판단하는 것을 권합니다 (§13 D-day 계획에 포함).

### 🔧 백엔드

| 항목 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | **Python + FastAPI** | 담당자 익숙한 언어. 비동기 처리로 STT/LLM 병렬 호출 |
| 배포 | 전시 현장 **로컬 머신** + 유선 LAN | 컨셉 11장 「네트워크 장애」 대응. 헤드셋과 같은 공유기에 물림 |
| STT | 📐 **스트리밍 STT** (Whisper API 또는 국내 실시간 STT) | 반드시 스트리밍. 배치 방식은 지연 예산을 초과합니다 (§10) |
| LLM | 📐 외부 API (온도 0.2, JSON 강제) | 응답 60토큰 이하로 제한 |
| 세션 저장 | 메모리 딕셔너리 (Redis 불필요) | 동시 세션 최대 3 |
| 콘텐츠 매니페스트 | JSON 파일 (DB 없음) | 아트·기획팀이 직접 편집 |

### 🔧 레이어 원칙

1. **연출 결정은 전부 백엔드에서.** 프론트엔드는 "무엇을 재생할지" 판단하지 않고, 받은 id를 재생만 합니다. 판정 규칙을 바꿀 때 프론트엔드를 다시 빌드하지 않아도 됩니다.
2. **매니페스트는 백엔드가 소유.** 아트·기획팀이 `manifest.json`을 고치면 새로고침만으로 반영됩니다.
3. **준언어 계산은 클라이언트.** 오디오 왕복을 한 번으로 줄입니다.
4. **프론트엔드는 백엔드가 죽어도 끝까지 진행.** 모든 요청에 로컬 기본값 폴백이 있습니다 (§11).

## 5. 판정 엔진 명세

### 5.1 장르 벡터

🔧 `G = {horror, romance, comedy, fantasy}`, 각 `0.0~1.0`, **합 = 1.0**
표기 코드: `H` `R` `C` `F`

### 5.2 텍스트 채점 (LLM)

🔧 **요청 명세**

```
temperature: 0.2
max_tokens: 60
response_format: JSON
```

📐 **프롬프트 골자** (`prompts/genre_score_v1.txt`)

```
너는 관객의 한국어 발화 한 문장을 네 장르의 정서 비율로 채점한다.

장르 정의
- horror   : 여기 오래 있으면 안 될 것 같다 (불안, 경계, 위협감)
- romance  : 누군가가 그립다 (그리움, 애착, 상실)
- comedy   : 어색하고 조금 우스꽝스럽다 (엉뚱함, 자기비하, 가벼움)
- fantasy  : 여기 어딘가 이상하다 (비현실감, 몽롱함, 초현실)

규칙
1. 네 값의 합은 정확히 1.0. 소수 둘째 자리까지.
2. 억지로 고르게 나누지 말 것. 한 장르가 뚜렷하면 0.6 이상을 줘도 된다.
3. 발화가 5음절 이하이거나 의미가 없으면 네 값을 모두 0.25로 반환한다.
4. 설명 없이 JSON만 출력한다.

출력 형식
{"horror":0.0,"romance":0.0,"comedy":0.0,"fantasy":0.0}
```

🔧 **few-shot 6건 필수 포함.** 최소 다음 케이스:
1. 컨셉 문서의 간판 예시 — "예전에 좋아했던 사람이랑 여기 자주 왔었는데... 지금은 좀 무섭네요." → `{H:0.40, R:0.50, C:0.00, F:0.10}`
2. 뚜렷한 단일 장르 1건
3. 짧은 발화 ("몰라요") → 균등
4. 농담 섞인 발화 1건
5. 비현실적 진술 1건
6. 무채색이 나와야 하는 애매한 발화 1건

🔧 **실패 처리:** JSON 파싱 실패 또는 합이 `1.0 ± 0.05` 밖 → 1회 재시도 → 재실패 시 `{0.25, 0.25, 0.25, 0.25}` 반환 (자동으로 기준값A 미달 → 재질문으로 흐름)

🔧 **개발용 캐시:** `sha256(transcript)` 키로 결과 캐싱. 같은 문장으로 반복 테스트할 때 API 비용과 대기 시간을 없앱니다.

### 5.3 준언어 채점 (규칙표)

🔧 클라이언트가 측정해 전송하는 값:

| 필드 | 단위 | 측정 방법 |
|---|---|---|
| `rms_mean` | 0~1 | AnalyserNode 시간영역 RMS 평균 |
| `rms_std` | 0~1 | 같은 값의 표준편차 |
| `f0_mean` | Hz | 자기상관 기반 피치 추정 (20ms 프레임) |
| `f0_cv` | 비율 | `f0_std / f0_mean` — 떨림 지표 |
| `speech_sec` | 초 | 유성 구간 총 길이 |
| `pre_silence_sec` | 초 | 질문 종료부터 발화 시작까지 |
| `syllable_rate` | 음절/초 | 에너지 피크 카운트 ÷ `speech_sec` (근사) |

📐 **가중 규칙** (초기값. 모두 가산 후 정규화)

| 조건 | H | R | C | F |
|---|---|---|---|---|
| 기본값 (모든 케이스에 가산) | 0.25 | 0.25 | 0.25 | 0.25 |
| `rms_mean < 0.02` (작게 말함) | +0.15 | — | −0.10 | +0.10 |
| `rms_std > 0.12` (음량 기복 큼) | — | — | +0.15 | — |
| `f0_cv > 0.25` (목소리 떨림) | +0.15 | +0.05 | — | — |
| `syllable_rate < 2.5` (느림) | +0.05 | +0.10 | −0.10 | +0.05 |
| `syllable_rate > 5.0` (빠름) | — | −0.05 | +0.15 | — |
| `pre_silence_sec > 3.0` (뜸들임) | +0.20 | +0.05 | — | +0.10 |
| `speech_sec < 1.5` (아주 짧음) | +0.10 | — | — | +0.05 |

🔧 음수 결과는 0으로 클램프한 뒤 합이 1이 되도록 정규화.

🔧 **완전 무응답** (12초 타임아웃): 규칙표를 건너뛰고 고정값
`P = {H: 0.45, F: 0.35, R: 0.15, C: 0.05}` — 컨셉 7장 "침묵이 길수록 공포·판타지"를 수치화.

### 5.4 융합

컨셉 문서의 미결 항목 「텍스트와 목소리 신호를 합치는 정확한 비율」 →

📐 **고정 비율이 아니라 발화 길이에 따라 바꿉니다.** 짧은 발화에서는 텍스트를 믿을 수 없기 때문입니다.

| 전사 음절 수 | `w_text` | `w_prosody` |
|---|---|---|
| 12음절 이상 | **0.75** | 0.25 |
| 5~11음절 | **0.55** | 0.45 |
| 4음절 이하 | **0.30** | 0.70 |
| 무응답 / STT 실패 | **0.00** | 1.00 |

```
G = normalize(w_text · T + w_prosody · P)
```

이 한 가지로 "관객이 짧게 답하면 판정이 무너진다"는 컨셉 4장의 우려가 해소됩니다.

### 5.5 기준값과 판정

🔧 **기준값A — 1위 최저선. Q1 직후에만 사용.**

```
max_score  = max(G)
entropy_n  = -Σ(g · log g) / log 4       # 0~1, 1이면 완전 균등

if max_score < 0.35 OR entropy_n > 0.95:
    → REASK (단 1회. 2회차에는 이 검사를 건너뛰고 강제 확정)
else:
    → event = argmax(G)
```

⚠️ **엔트로피 조건이 왜 필요한가:** `max_score`만 보면 `{0.36, 0.34, 0.15, 0.15}`도 `{0.36, 0.22, 0.21, 0.21}`도 통과합니다. 앞쪽은 **좋은 혼합**입니다(1·2위가 붙은 것은 컨셉 7장이 명시적으로 환영한 상태). 뒤쪽은 컨셉 3장의 **"탁한 무채색"**입니다. `max_score` 단독으로는 이 둘을 구분하지 못합니다. 엔트로피가 구분해 줍니다.

🔧 **임계 0.95의 근거** — 실제 계산해 본 분리 결과입니다.

| 벡터 | `max` | `entropy_n` | 판정 | 성격 |
|---|---|---|---|---|
| 0.25 / 0.25 / 0.25 / 0.25 | 0.25 | **1.000** | REASK | 완전 무채색 |
| 0.36 / 0.22 / 0.21 / 0.21 | 0.36 | **0.978** | REASK | 무채색 |
| 0.38 / 0.24 / 0.19 / 0.19 | 0.38 | **0.968** | REASK | 무채색 |
| 0.40 / 0.20 / 0.20 / 0.20 | 0.40 | **0.961** | REASK | 무채색 경계 |
| ⎯⎯ 임계 0.95 ⎯⎯ | | | | |
| 0.36 / 0.34 / 0.15 / 0.15 | 0.36 | **0.940** | 통과 | 좋은 혼합 (1·2위 접전) |
| 0.40 / 0.35 / 0.15 / 0.10 | 0.40 | **0.901** | 통과 | 좋은 혼합 |
| 0.50 / 0.40 / 0.10 / 0.00 | 0.50 | **0.680** | 통과 | 컨셉 문서 간판 예시 |
| 0.70 / 0.15 / 0.10 / 0.05 | 0.70 | **0.660** | 통과 | 순수에 가까움 |

무채색 최저치 0.961과 좋은 혼합 최고치 0.940 사이에 여유가 0.02밖에 없습니다. **0.93으로 잡으면 좋은 혼합까지 재질문 대상이 되어 버립니다** — 컨셉 7장이 경고한 바로 그 실수입니다. 0.95가 두 군집을 가장 깔끔하게 가릅니다.

🔧 **기준값B — 2위 최저선. Q2 직후에만 사용.**

```
G2 = Q2 발화의 장르 벡터
second = argmax(G2 중 event 제외)   # 사건 장르를 뺀 나머지 3개의 1위

if G2[event] == max(G2) OR max(G2 제외 event) < 0.20:
    → attitude = event        # 순수(강화) 배합
else:
    → attitude = second       # 혼합 배합
```

📐 초기값 **기준값A = 0.35 / 엔트로피 = 0.95 / 기준값B = 0.20**.
🔴 세 값 모두 8월 두 사람 실험에서 실측 조정합니다. 조정 목표는 **재질문율 15~30%**, **순수 배합 비율 20~35%**. 재질문이 30%를 넘으면 기준값A를 0.32로 내리고, 순수 배합이 절반을 넘으면 기준값B를 0.16으로 내립니다.

### 5.6 연출 강도

🔧 상위 두 장르만 연출에 반영 (컨셉 3장 규칙). 3·4위는 값을 계산하되 **게인 0, 조명 반영 0**.

```
intensity        = clamp((max_score - 0.35) / 0.40, 0.0, 1.0)
attitude_weight  = clamp(G1[attitude] / G1[event], 0.0, 1.0)
```

🔧 `attitude_weight`는 **Q1 벡터(`G1`)** 기준입니다. Q2 벡터는 태도를 *고르는* 데만 쓰고, 태도의 *세기*는 카드에 인쇄되는 Q1 점수와 일치해야 합니다. 그렇지 않으면 카드의 숫자와 관객이 본 화면이 어긋납니다.

- `intensity` → 형광등 점멸 빈도, 안개 농도, 그림자 길이, 마스터 볼륨의 스칼라
- `attitude_weight` → lightmap 크로스페이드의 `t`, 2위 stem의 게인

순수 배합에서는 `attitude_weight = 1.0`이 되어 프리셋 한 장이 100% 적용됩니다 — 컨셉 4장 "같은 장르가 강조됨. 응답이 뚜렷할수록 세게"와 일치합니다.

```json
}
```

📐 `stems`는 매니페스트에 **넣지 않습니다.** 어느 stem이 울릴지는 배합 ID에서 도출되고, 게인은 서버가 `attitude_weight`로 계산합니다 (§7.2). 아트·기획팀이 손으로 유지할 필드를 줄이는 편이 안전합니다.

### 🔧 아트·기획팀이 만들 최소 목록 (컨셉 5장 목록의 개수 수정 반영)

- [ ] 조명 프리셋 **5~8세트** (순수 4 + 대표 조합 3~4)
- [ ] 핵심 3D 소품 8~10개
- [ ] 장르별 상징 소품 4개
- [ ] NPC 사건 4종 · 연기 층 **4종**
- [ ] NPC 문장 층 **16벌 · 약 56줄** ← 컨셉 문서의 "12벌"에서 수정 (§1 구멍 2)
- [ ] 도착 버스 4종
- [ ] texture 팔레트 1세트 (채도 15% 이하)
- [ ] 콜백 템플릿 16개(텍스트) + 폴백 문장 16개 음성 ← 컨셉 문서에 없던 항목 (§8)
- [ ] 노선도·버스 행선지 표시판 — **글자를 런타임에 그려 넣을 수 있는 구조**로 제작 (§8)
- [ ] 배합 이름 **16개** ← 혼합 12 + 순수 4

📐 **순수 4개 배합 이름 초안** (컨셉 13장의 미결 항목)

| ID | 이름 초안 |
|---|---|
| H-H | 여기 있어선 안 될 밤 |
| R-R | 오지 않는 사람 |
| C-C | 아무 일도 아닌 밤 |
| F-F | 어디도 아닌 정류장 |

## 7. 연출 매핑 — 조명 · 오디오 · NPC

### 7.1 🔧 조명 크로스페이드

**셰이더 요구사항** (PlayCanvas 셰이더 chunk 1회 작성)

```glsl
// 표준 lightmap chunk를 교체
uniform sampler2D texture_lightMapA;
uniform sampler2D texture_lightMapB;
uniform float uBlendT;      // 0.0 = A 전량, 1.0 = B 전량

vec3 lm = mix(
    texture2D(texture_lightMapA, vUv1).rgb,
    texture2D(texture_lightMapB, vUv1).rgb,
    uBlendT
);
```

**주변광·안개·하늘 색**은 프리셋 json의 값 사이를 **RGB 선형 보간**합니다.
🔧 컨셉 5장이 경고한 "청록→자주 사이에 초록이 낀다"는 문제는 HSV 색상환을 돌 때만 발생합니다. 인접한 프리셋 두 장의 RGB 선형 보간은 색상환을 돌지 않으므로 안전합니다. **HSV 보간은 코드베이스 전체에서 금지합니다.**

🔧 전환 파라미터

| 항목 | 값 |
|---|---|
| 1차 전환 (S6, 사건 확정) | 중립 → `lp_{event}` 100%, **4.0초** ease-in-out |
| 2차 전환 (S11, 배합 확정) | `lp_{event}` → `mix(lp_event, lp_attitude, t)`, **6.0초** |
| `t` 값 | `attitude_weight × 0.45` (최대 0.45 — 태도는 사건을 덮지 않음) |
| 안개 농도 | `base + intensity × 0.4` |
| 형광등 점멸 주기 | `H` 비중이 클수록 짧게. `4.0s − intensity × 3.0s` |

📐 `t` 상한을 0.45로 둔 이유: 태도가 사건보다 강하게 보이면 "무슨 일이 일어났는가"의 인상이 흐려집니다. 컨셉 4장의 사건/태도 위계를 조명에서도 유지합니다.

### 7.2 🔧 오디오 4-stem 믹싱

```
                          ┌─ GainNode(H) ─┐
audio buffer stem_H ──────┤               │
audio buffer stem_R ──────┤ GainNode(R)   ├── MasterGain ── Destination
audio buffer stem_C ──────┤ GainNode(C)   │
audio buffer stem_F ──────┤ GainNode(F) ──┘
```

🔧 **4개 stem은 S2에서 전부 동시 재생 시작하고 끝까지 멈추지 않습니다.** 게인만 바꿉니다. 이렇게 하면 위상이 어긋나지 않아 전환이 부드럽습니다.

🔧 **등가전력 게인 산출** (단순 선형 합산은 볼륨이 출렁입니다)
§3 원칙에 따라 이 계산은 **서버**에서 수행하고, 클라이언트는 받은 게인을 그대로 적용합니다.

```python
w1 = 1.0                          # 사건
w2 = attitude_weight * 0.7        # 태도 (최대 0.7)
norm = sqrt(w1**2 + w2**2)

gain[event]    = w1 / norm
gain[attitude] = w2 / norm
gain[나머지 2개] = 0.0             # 컨셉 3장 상위 2개 원칙
```

**계산 예** — `R-H`, `attitude_weight = 0.80`
`w2 = 0.56`, `norm = 1.146` → `gain[R] = 0.873`, `gain[H] = 0.489`, `gain[C] = gain[F] = 0.0`

🔧 순수 배합에서는 `event === attitude`이므로 `gain[event] = 1.0` 단일 채널. 의도한 동작입니다.

🔧 게인 변경은 `setTargetAtTime(value, now, 1.5)` — 계단식 점프 금지.

🔧 **NPC 음성과 버스 소리는 stem 버스를 타지 않습니다.** 별도 `PannerNode`(HRTF)로 공간화. NPC는 벤치 옆 좌표, 버스는 접근 궤적을 따라 이동.

### 7.3 🔧 NPC 재생 구조

NPC의 두 층은 **재생 시점이 다릅니다.**

| 층 | 무엇 | 언제 | 어떻게 |
|---|---|---|---|
| **연기 층** (4종) | 시선, 거리, 침묵 길이, 몸짓 | S11에서 클립 교체, S12 전체에 적용 | `anim_att_{A}.glb` 애니메이션 클립 + 위치 오프셋 파라미터 |
| **문장 층** (16벌) | 어미, 시제, 문장 끊김 | S12에서 대사 재생 | `line_blend_{E}-{A}_{n}.ogg` 순차 재생 |

🔧 **연기 층 파라미터** (애니메이션 외에 코드로 제어)

| 태도 | 시선 접촉률 | 벤치 거리(m) | 대사 사이 침묵(s) | 음성 볼륨 |
|---|---|---|---|---|
| 🖤 H | 0.15 | 0.9 → 1.4 (물러남) | 1.8 | 0.75 |
| 💗 R | 0.70 | 0.9 → 0.5 (다가옴) | 2.5 | 0.85 |
| 💛 C | 0.45 | 0.9 (고정) | 0.4 (겹치듯 빠르게) | 1.10 |
| 💜 F | 0.30 (허공 응시 병행) | 0.9 (고정) | 1.2 | 0.90 |

🔧 `S7`(사건 대사)에서는 연기 층이 아직 확정되지 않았으므로 **중립 연기**를 사용합니다: 시선 0.40, 거리 0.9 고정, 침묵 1.5s, 볼륨 0.9.

### 7.4 🔧 버스 도착 시퀀스 (S13, 70초)

| 구간 | 내용 |
|---|---|
| 0–20s | 원거리 엔진음 페이드인(공간화, 좌→우), 전조등 빛이 안개를 가름 |
| 20–40s | 버스 접근. `bus_{event}.glb` 등장. stem 게인 −6dB로 눌러 버스 소리에 자리를 내줌 |
| 40–60s | 사건별 고유 연출 (아래) |
| 60–70s | 화이트/블랙 페이드 → S14 |

| 사건 | 40–60초 구간 |
|---|---|
| 🖤 H | 전조등만. 실내 완전 암전. "탑승하시겠습니까" 안내음 3회 반복 |
| 💗 R | 창에 흐릿한 실루엣 1개. 낯익은 멜로디(stem_R의 모티프 재활용). 빈자리 하나 강조광 |
| 💛 C | 문이 열리려다 멈춤 ×2. 기사 실루엣이 창 너머로 손짓, 소리는 유리에 막혀 저역만 |
| 💜 F | 창가에 관객과 같은 실루엣. 그 실루엣이 천천히 고개를 돌려 관객을 봄 |

🔴 `F` 버스의 "나와 같은 얼굴"은 관객 얼굴을 알 수 없으므로 **실루엣과 자세로만** 표현합니다. 벤치에 앉은 관객과 동일한 앉은 자세, 동일한 머리 실루엣. 얼굴 렌더링을 시도하면 불쾌한 골짜기에 빠집니다.

## 8. 명사 콜백 구현 명세

§1 구멍 1의 해결안입니다. 컨셉 문서가 가장 높게 평가한 장치이므로 별도 장으로 다룹니다.

### ⚠️ 초판 수정 — 문제를 잘못 잡았습니다

이 문서 초판은 명사 콜백을 **지연 문제**로 놓고, 명사 80개를 미리 합성해 오디오를 이어붙이는 스플라이싱 방식을 골랐습니다. 틀렸습니다.

**§4 타임라인을 보면 지연이라는 문제가 존재하지 않습니다.**

| 시점 | 사건 |
|---|---|
| **1:40** | Q1 채점 완료 → 명사 확보 |
| **5:10** | 배합 확정 → 콜백 문장 완성 가능 |
| **6:50** | 콜백 재생 |

명사는 콜백보다 **5분 10초 먼저**, 배합은 **1분 40초 먼저** 확정됩니다. 런타임 합성 1~3초는 이 여유 앞에서 무의미합니다. 초판이 "지연 1.5~2.5초"를 이유로 기각한 A안이 정답이었습니다.

그리고 스플라이싱 방식에는 초판이 덮어 둔 결함이 셋 있었습니다.

| 결함 | 내용 |
|---|---|
| **낱말 억양** ★치명적 | 단독 합성한 명사는 문장 끝 억양(하강 피치 + 장음화)을 갖습니다. 문장 중간에 끼우면 *"아직 그 · 친구↘ · 안 왔네요"* 세 토막으로 들립니다. 초판의 "80ms 패딩 / −60ms 겹침"은 **시간**을 다룬 것이고 이건 **피치·길이** 문제라 해결되지 않습니다 |
| **조사 분기** | 받침 유무로 "이/가", "은/는", "와/과"가 갈립니다. 캐리어 문장이 조사를 요구하면 suffix를 배합당 2벌씩 만들어야 합니다 (16 → 32벌) |
| **목록 크기** | 80개는 근거 없이 정한 숫자입니다. 목록 밖 명사는 그대로 폴백으로 떨어지고, 폴백이 잦으면 장치 자체가 죽습니다 |

### 🔧 수정안 — 미리 굽는다 (pre-bake)

문장 **전체**를 런타임에 합성해 버퍼에 담아 두고, 시간이 되면 재생합니다.

```
1:40   Q1 채점 → 명사 추출("친구") → 서버 세션에 보관
         │
5:10   배합 확정(R-H) → 템플릿에 명사 삽입
         │            "...아직 그 친구 안 왔네요."
         ├─→ TTS 합성 (1~3초, 문장 단위 한 번)
         ├─→ 오디오를 클라이언트로 전송 → AudioBuffer 디코드
         └─→ 실패 시 3회 재시도. 예산 100초 (30배 여유)
         │
6:40   버퍼 확인. 비어 있으면 폴백으로 전환 결정
6:50   재생
```

**이 방식이 세 결함을 전부 없앱니다.**

| 항목 | 스플라이싱 (초판) | 미리 굽기 (수정) |
|---|---|---|
| 억양 | 세 토막으로 들림 | 문장 하나로 합성 → **이음새 없음** |
| 조사 | suffix 32벌 필요 | 텍스트 단계에서 처리 → **오디오 영향 없음** |
| 명사 범위 | 화이트리스트 80개 | **제한 없음. 어떤 명사든** |
| 목소리 | 일치 | 일치 (동일 TTS 설정) |
| 실효 지연 | 0 | **0** (100초 전에 준비 완료) |
| 추가 에셋 | 128 조각 | **16개** (폴백 문장만) |
| 네트워크 의존 | 없음 | 있음 → 아래에서 제거 |

### 🔧 조사 처리 (받침 판정)

텍스트 단계에서 끝납니다. 5줄입니다.

```python
def has_jong(word: str) -> bool:
    """마지막 글자에 받침이 있는가"""
    ch = ord(word[-1])
    if not (0xAC00 <= ch <= 0xD7A3):   # 한글 음절이 아니면
        return False
    return (ch - 0xAC00) % 28 != 0

def josa(word: str, with_jong: str, without_jong: str) -> str:
    return word + (with_jong if has_jong(word) else without_jong)

# josa("친구", "이", "가")  → "친구가"
# josa("동생", "이", "가")  → "동생이"
```

📐 템플릿에는 조사 자리를 명시합니다: `"...아직 그 {noun} 안 왔네요."` (조사 없음) / `"{noun|이:가} 오기로 했었나요."` (조사 분기)

### 🔧 템플릿 명세

배합 16개마다 콜백 템플릿 1개 + 명사 없는 폴백 문장 1개.

```json
"R-H": {
  "callback": {
    "template": "...아직 그 {noun} 안 왔네요.",
    "fallback_audio": "line_blend_R-H_cb_fallback",
    "play_at_ms": 105000,
    "prepare_by_ms": 100000
  }
}
```

🔧 `prepare_by_ms`까지 버퍼가 준비되지 않으면 `fallback_audio`(사전 녹음, 명사 없는 완결 문장)로 전환합니다. 예: `"...아직 안 오네요."`

### 🔧 명사 추출 규칙

```python
# 1. 조사 제거 후 명사 후보 추출 (형태소 분석 또는 LLM 1회 호출로 동시 처리)
# 2. 여러 개면 → 관객이 마지막에 말한 것 (문장 끝에 가까운 명사가 심리적으로 더 무겁다)
# 3. 대명사·지시어·정류장 자체를 가리키는 말은 제외 (그거, 이거, 여기, 버스, 정류장)
# 4. 명사가 하나도 없으면 → fallback_audio
```

📐 **명사 추출은 §5.2의 장르 채점 LLM 호출에 필드 하나를 추가해 같이 받습니다.** 별도 호출이 필요 없습니다.

```json
{"horror":0.40,"romance":0.50,"comedy":0.00,"fantasy":0.10,"noun":"친구"}
```

🔧 "버스"와 "정류장"을 제외하는 이유: 관객 대부분이 이 단어를 말합니다. NPC가 *"아직 그 버스 안 왔네요"*라고 하면 콜백이 아니라 그냥 상황 설명이 되어 버립니다. 콜백은 **관객만 말한 것**이어야 효과가 있습니다.

### 🔧 네트워크 의존 제거 — 2단 방어

미리 굽기의 유일한 약점은 콜백 시점에 TTS API가 필요하다는 것입니다. 두 단계로 없앱니다.

**1단계 (9월) — 현장 로컬 TTS**
전시 현장 머신에서 돌아가는 한국어 TTS 모델을 사용합니다(§2에서 백엔드를 현장 로컬 머신에 두기로 이미 정했습니다). 그러면 네트워크 의존이 **0**이 됩니다. 대사 사전 합성도 같은 모델로 하면 목소리가 자동으로 일치합니다.

🔴 이것을 하려면 **모든 사전 합성 음성을 로컬 모델로 만들어야 합니다.** 외부 API로 대사를 굽고 콜백만 로컬 모델로 하면 목소리가 어긋납니다. 9월 대사 녹음을 시작하기 **전에** 모델을 확정해야 합니다.

**2단계 (무료) — 세계 안 텍스트로 한 번 더**

음성과 별개로, **명사를 정류장 안에 글자로 배치합니다.**

| 위치 | 무엇 | 근거 |
|---|---|---|
| 노선도의 정류장 이름 한 칸 | `{noun}앞` / `{noun}입구` | 컨셉 5장이 "코팅이 벗겨진 노선도"를 이미 에셋 목록에 넣었습니다 |
| 버스 행선지 표시 | `{noun}` 방면 | 컨셉 5장 "스스로 빛나는 물체"에 이미 표지판·버스 전조등이 포함 |

🔧 런타임 텍스처 렌더링(캔버스 → 텍스처). 네트워크 불필요, 지연 0, 실패 없음.

📐 **음성 콜백보다 이쪽이 강할 수도 있습니다.** 자막이 아니라 **세계의 일부**이고, 관객이 스스로 발견합니다. "이 정류장 이름이 내가 말한 단어네" — 컨셉 문서가 원한 *"너 나랑 다른 걸 봤네"*를 직접 만들어냅니다. 그리고 음성 콜백이 어떤 이유로든 실패해도 이건 남습니다.

🔴 어둠 속 저해상도에서 한글 가독성이 확인되어야 합니다. **8/12 화이트박스 씬에서 30분 테스트**로 판단하세요 — 안 읽히면 표지판을 관객 가까이 당기거나 자체발광 강도를 올립니다.

### 🔧 폴백 체인 (최종)

```
TTS 버퍼 준비됨 (6:40 기준)  →  재생. 세계 안 텍스트도 함께
        ↓ 미준비
fallback_audio 재생 (명사 없는 완결 문장) + 세계 안 텍스트는 그대로
        ↓ 명사 자체가 추출되지 않음
fallback_audio 재생. 세계 안 텍스트는 기본값("종점", "차고지")
```

🔧 어느 경로에서도 관객은 **무언가 들으며** 지나갑니다. 침묵이 생기는 분기는 없습니다.

### 🔧 `GET /session/{id}/callback.ogg`

미리 구운 콜백 음성. `LOCK_BLEND` 응답 직후 클라이언트가 폴링(2초 간격, 최대 45회)합니다.

| 상태 | 응답 |
|---|---|
| 합성 진행 중 | `202 Accepted` |
| 완료 | `200` + `audio/ogg` |
| 실패 (3회 재시도 소진) | `503` → 클라이언트는 `fallback_audio`로 확정 |

🔧 오디오는 **한 번 내려간 뒤 서버 메모리에서 삭제**합니다. 디스크에 쓰지 않습니다 (§12).

🔧 **`transcript`는 응답에 포함하지 않습니다.** §12 개인정보 방침. 시연용 HUD에 전사를 띄워야 하는 8월 22일에만 `?debug=1` 쿼리로 반환하고, 전시 빌드에서는 이 경로를 삭제합니다.

### 🔧 `POST /session/{id}/silence`

무응답 신고. 본문 `{"stage": "Q1", "consecutive": 2}`
서버는 §5.3 무응답 고정값으로 채점해 동일한 형식으로 응답합니다.
🔧 `consecutive >= 3` → 기본 경로 강제 확정. 📐 **기본 경로 = `H-F` (「이 세계가 아닌 무언가의 시선」)** — 컨셉 7장 "침묵은 공포·판타지로" 규칙의 논리적 귀결.

## 10. 지연 예산과 마스킹

### 🔧 예산표 (발화 종료 → 조명 확정 전환 시작)

| 단계 | 배치 STT | **스트리밍 STT** |
|---|---|---|
| VAD 발화 종료 판정 (침묵 700ms) | 700ms | 700ms |
| 오디오 업로드 (5초 발화 ≒ 40KB, LAN) | 150ms | **0** (발화 중 전송 완료) |
| STT | 900ms | **150ms** (마지막 조각만) |
| LLM 채점 | 1,100ms | 1,100ms |
| 판정 + 매니페스트 조회 | 20ms | 20ms |
| 응답 수신 + 전환 시작 | 80ms | 80ms |
| **합계** | **2,950ms** | **2,050ms** |

🔧 **스트리밍 STT는 선택이 아니라 요구사항입니다.** 배치 방식은 컨셉 7장의 "목표 지연 2초"를 구조적으로 달성할 수 없습니다.

📐 LLM 1,100ms를 더 줄이려면: `max_tokens=60` 유지 + 프롬프트 캐싱 + 더 작은 모델. 8월 시연에서 실측 후 판단.

### 🔧 마스킹 연출 (S5 · S10 진입 즉시, API 호출과 동시)

**발화 종료가 감지된 순간 0ms에 발동합니다.** 서버 응답을 기다리지 않습니다.

| 시각 | 연출 | 비용 |
|---|---|---|
| 0ms | 안개가 한 번 훑고 지나감 (fog density 0.4초간 +30% 후 복귀) | 코드 3줄 |
| 200ms | 형광등 1회 깜빡임 (2프레임 소등) | 코드 3줄 |
| 600ms | NPC가 관객 쪽으로 고개를 돌림 (0.8초 회전) | 애니메이션 1개 |
| 1,400ms | NPC가 짧게 숨을 들이쉼 (음성 파일 1개, 배합 무관 공용) | 파일 1개 |
| 응답 도착 | 조명 크로스페이드 시작 | — |

📐 **4번(들숨)이 가장 강력합니다.** "이 사람이 내 말을 듣고 무언가 말하려 한다"는 신호이므로, 관객은 남은 지연을 **대화의 자연스러운 틈**으로 읽습니다.

🔧 **최악 시나리오 (응답 5초 초과):** 3,000ms 지점에서 NPC가 공용 채움 대사 1줄 재생 — `"...음."` / `"...그렇군요."` 배합과 무관하게 성립하는 짧은 것. 5,000ms 초과 시 §11의 로컬 폴백으로 전환.

## 11. 실패·폴백 처리 매트릭스

🔧 **원칙: 어떤 실패에서도 관객은 카드를 받고 나갑니다.** 오류 화면은 존재하지 않습니다.

| 실패 | 감지 | 대응 | 관객이 알아차리나 |
|---|---|---|---|
| 마이크 권한 거부 | `getUserMedia` reject | **시선 선택 모드**로 전환 — 정류장에 부유 오브젝트 3개, 3초 응시로 선택. 사건·태도를 각각 이 방식으로 결정 | 안내 문구로 명시 |
| STT 실패/타임아웃(3s) | 서버 | `w_text=0`, 준언어 100%로 채점 (§5.4) | ❌ |
| LLM 실패 | 서버 | 1회 재시도 → 균등분포 → 재질문 → 2회차도 실패 시 준언어 100% | ❌ |
| 백엔드 무응답 (5s) | 클라이언트 | **로컬 폴백 판정** — 클라이언트가 준언어 규칙표만으로 자체 채점. 매니페스트는 이미 프리로드되어 있음 | ❌ |
| 백엔드 완전 다운 | `/session` 실패 | 로컬 폴백 판정으로 전 세션 진행. 재질문 없음 | ❌ |
| 네트워크 단절 | — | 유선 + 무선 이중화. 둘 다 끊기면 로컬 폴백 | ❌ |
| 관객 무응답 1~2회 | 12s 타임아웃 | NPC 혼잣말 유도 1줄 → 재시도 | 자연스러움 |
| 관객 무응답 3회 | — | 기본 경로 `H-F` 강제 확정 | ❌ |
| 프레임 저하 (<60fps 3초) | 클라이언트 | 안개 품질 하향 → 실시간 조명 3→1개 → 그림자 해제 (3단계 자동) | 미미 |
| 오디오 컨텍스트 정지 | `state !== 'running'` | 사용자 제스처로 `resume()`. GATE 단계에서 미리 확보 | ❌ |
| 헤드셋 트래킹 상실 | WebXR 이벤트 | 세션 일시정지, 오디오 유지, 복귀 시 재개 | 자연스러움 |
| 세션 중 이탈 | `visibilitychange` | 30초 후 자동 RESET | — |

🔧 **로컬 폴백 판정**은 반드시 구현합니다. 전시 당일 백엔드 문제로 작품 전체가 멈추는 것을 막는 유일한 장치입니다. 준언어 규칙표는 순수 산술이므로 클라이언트 이식이 30줄입니다.

📐 **최후의 폴백:** 컨셉 11장이 언급한 "미리 녹화한 영상". 순수 4종 × 3분 영상을 USB에 준비하되, 위 폴백들이 작동하면 쓸 일이 없습니다.

## 12. 개인정보 · 로깅 명세

### 🔧 음성 데이터 수명

```
마이크 → MediaRecorder 버퍼 (브라우저 메모리)
   → HTTPS 업로드 → FastAPI 요청 스코프 (서버 메모리)
   → STT API 전송 → 전사 문자열 (서버 메모리)
   → LLM 채점 + 명사 매칭
   → 응답 반환
   → ★ 오디오 바이트와 전사 문자열 폐기 (dispose)
     단, 추출된 명사 1개는 세션 종료 시까지 메모리 보관 (§8 콜백용)
     → 세션 종료 시 폐기. 로그에는 남기지 않음
```

🔴 **명사 1개는 예외적으로 세션 동안 보관됩니다.** 콜백 음성과 표지판 글자에 필요하기 때문입니다. 이 단어는 해당 관객 본인의 헤드셋으로만 돌아가고, 로그·디스크·외부에는 기록되지 않습니다. TTS API로는 이 단어가 포함된 문장이 전송됩니다 — §12 마지막의 벤더 정책 확인 항목에 TTS도 포함해야 합니다.

🔧 **구현 규칙 (코드 리뷰 필수 항목)**
- 오디오를 `tempfile`이나 디스크에 절대 쓰지 않음. `BytesIO`만 사용
- 전사 문자열을 로거에 넘기지 않음. `logging` 호출에 `transcript` 변수 금지
- 응답 JSON에 `transcript` 필드 없음 (`?debug=1`은 시연 전용, 전시 빌드에서 라우트 삭제)
- STT·LLM 외부 API의 **데이터 보관 정책 확인 필요**. 학습 미사용 옵션을 켜야 합니다 🔴

### 🔧 로그에 남기는 것

```json
{
  "session_id": "s_7f3a91",
  "ts": "2026-08-22T14:31:02Z",
  "stage": "Q1",
  "scores": {"horror":0.40,"romance":0.50,"comedy":0.00,"fantasy":0.10},
  "syllables": 18,
  "w_text": 0.75,
  "entropy_n": 0.71,
  "action": "LOCK_EVENT",
  "noun_extracted": true,
  "callback_source": "tts",
  "latency_ms": {"stt": 160, "llm": 1080, "total": 2040}
}
```

🔧 `syllables`는 **개수만**, 내용 없음. `noun_extracted`는 **불리언**이며 단어 자체를 남기지 않습니다. `callback_source`는 `"tts"` \| `"fallback"` — §8 폴백 발동률을 집계하는 유일한 지표입니다.
🔧 `session_id`는 난수. 관객 식별 정보와 연결되지 않습니다.

### 🔧 관객 고지

입구 안내판과 체험 시작 안내에 명시 (컨셉 12장):
- 목소리는 점수를 매기는 데만 사용됩니다
- 음성 원본과 변환된 글자는 그 자리에서 폐기됩니다
- 남는 것은 네 개의 숫자와 배합 이름뿐입니다

🔴 **8월 두 사람 실험은 대화를 녹음하므로 별도 동의서가 필요합니다.** 기획팀 작성, **8/17까지**. 포함 항목: 녹음 목적, 보관 기간(분석 완료 후 폐기), 발표 자료에 음성 사용 여부(별도 체크박스), 철회 방법.

5. **커밋 메시지에 기준값 변경 시 이전값 기록.** 시연 중 되돌릴 수 있어야 합니다.
