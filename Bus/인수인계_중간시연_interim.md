## 2. 지금 되는 것 (구현 완료)

| 스펙상 신호 | 무엇을 보는가 | 구현 상태 |
|---|---|---|
| S1 관심 | 길 건너 판초 인물을 얼마나 지속·반복해서 보는가 | ✅ 헤드셋/드래그 머리 방향으로 실측 |
| S2 놀람 | 트럭 물웅덩이 튀김에 놀라는가 | ✅ 웹캠 표정 + 마이크(단발 큰 소리) |
| S3 호기심 | 찢어진 포스터를 몸 돌려 읽는가 | ✅ 헤드셋/드래그 머리 방향으로 실측 |
| S4 정서 | 고양이와 눈맞춤에 웃는가/무서워하는가 | ✅ 웹캠 표정 + 마이크(반복 웃음소리) |
| S5 경계 | 등 뒤 개구리에 돌아보는가/기피하는가/**기립**하는가 | ✅ 머리 방향 + **헤드셋 높이(Y) 변화로 기립 감지** |

판정 로직(`lib/interimJudge.js`)은 스펙 §3의 점수표를 그대로 구현했고, 신호가 하나도 없으면
"로맨스 디폴트", 특정 조합(S2·A + S5·A)이면 "공포 확정" 등 문서에 명시된 규칙을 그대로
따릅니다. 12개 케이스로 단위 검증했습니다.

관객이 보는 화면은 **정직하게** 무엇이 실제 센서로 연결됐고 무엇이 근사치인지 HUD에
표시합니다 (예: "웹캠: 거부됨", "기립 감지: 헤드셋 필요(데스크톱)").

## 3. 아직 못 채운 것 (하드웨어 한계, 코드로 해결 불가)

- **외부 몸 카메라**: 스펙은 관객 몸 전체를 보는 별도 카메라를 가정하지만, 지금은 관객
  얼굴을 향한 웹캠 하나뿐입니다. 그 웹캠(표정+고개 움직임)으로 "몸 반응"까지 근사하고
  있습니다. 실제 전시 부스에서 몸 카메라를 따로 설치하기 전까지는 이 근사치가 최선입니다.

## 4. 파일럿 전에 반드시 할 일

### (1) 임계값 실측 보정 — 스펙 §3-1 규칙⑤
지금 코드에 들어간 숫자는 전부 **잠정치**입니다. 실제 사람들 반응을 몇 번 보고 나서
아래 파일들만 고치면 됩니다 (다른 로직은 안 건드려도 됨):

- `lib/interimGrader.js` — 웹캠 놀람/웃음 민감도 (0.05 / 0.12 / 0.5 등)
- `lib/interimMic.js` — 소리 크기·반복 판단 기준 (0.05 / 0.15 / 0.5 등)
- `lib/standUpSense.js` — 기립 인정 기준 (28cm 이상, 1.2초 이내)

### (2) 3D 연출 미세조정
판초 인물이 걷는 경로와 기둥 뒤에서 NPC로 "정체가 드러나는" 타이밍(`lib/interimTimeline.js`)은
숫자로만 검증했고, 실제 3D 화면에서 눈으로 보면서 다듬는 작업이 아직 안 되어 있습니다.

### (3) 남은 산출물 (팀 작업, 코드 밖)
- 아트팀 GLB 3종(옆사람 캐릭터, 걷기/앉기/말하기 동작 포함) — 준비되는 대로 바로 교체 가능하게 만들어둠
- 인사 대사 TTS 음성 (지금은 자막만 있음)
- 20명 규모 헤드셋 파일럿 (발표 11/7 기준 1주 전 목표)

## 5. 테스트하는 법

URL 뒤에 파라미터를 붙이면 특정 신호를 강제로 지정해서 원하는 장르로 바로 끝까지
돌려볼 수 있습니다. (예시: 전체 재생을 20배속으로, S1·S3만 강제 A로 지정)

```
https://busstop-team.vercel.app/interim?s1=A&s3=A&speed=20
```

- `?s1=A` ~ `?s5=A` : 각 신호 등급 강제 지정 (A~E)
- `?speed=N` : 재생 속도 배수
- `?cam=0` : 웹캠 안 켜고 테스트
- `?mic=0` : 마이크 안 켜고 테스트

화면 우측(또는 하단) HUD에 실시간 장르 점수, 드리프트 %, 신호별 등급, 센서 연결 상태가
전부 표시됩니다.
