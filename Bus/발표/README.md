## 용어를 이렇게 정한 이유

초안에서 영어를 그대로 옮겨 **「디제틱 프로브」**, **「무요구」** 라고 썼다가 고쳤습니다.

- **디제틱(diegetic)** — 「디제시스」는 영화학에서 쓰는 말이 맞지만, 발표 첫 화면에
  전문어를 앞세우면 겉돕니다. → **서사 내재 자극**, 짧게 **자극**
- **무요구** — 표준어가 아니라 제가 만든 말입니다. 「유도(elicitation)」는
  심리학·언어학의 표준어이므로 그 부정형을 씁니다. → **비유도(非誘導)**,
  본문에서는 그냥 **"관객에게 아무것도 요구하지 않는"**

논문 제목의 영문 병기에는 원어(diegetic probe / non-elicited)를 남겨 두어
선행 연구와 이어지게 했습니다.

## 제목을 이렇게 잡은 이유

원 제안서의 핵심기술 문장은 "연속 파라미터 블렌딩"만 담고 있는데, 그것만으로는
해자가 약합니다. 게임 오디오 미들웨어가 파라미터 블렌딩을 이미 하고 있고,
LLM 대사 생성도 흔합니다.

방어되는 지점은 **비유도(non-elicited)** 입니다. 감정 인식 연구는 거의 전부
*유도된* 반응을 씁니다 — 자극 영상을 보여주고 재거나, 연기한 표정 데이터셋을
쓰거나, 직접 묻습니다. 이 작품은 그걸 하면 안 되고(v1.1 §2 "관객이 해야 할 일은
벤치에 앉아 버스를 기다리는 것뿐"), 그 제약을 정면으로 받으면 문제가
**"자유로운 얼굴 → 감정 라벨"에서 "알려진 시각·방위의 자극 → 반응 커널"** 로
바뀝니다. 그래서 제목에 두 축을 다 넣었습니다.

상세는 `Bus/규격/프로브_하네스.md` §5.

## 레이아웃 검사

장표는 한 장이 화면 하나에 정확히 들어가야 하고, 요소가 겹치면 안 됩니다.
눈으로 보는 대신 재서 확인합니다.

```bash
# 감사기를 주입한 사본을 만들고 헤드리스로 측정
# (실제 절차는 아래 결과와 함께 세션 기록에 있음)
```

마지막 검사 결과 — **4장 전부 겹침 0건, 넘침 0건**:

```
[s1] 내용 771px / 여유 824px → OK (53px 여유)
[s2] 내용 704px / 여유 824px → OK (120px 여유)
[s3] 내용 795px / 여유 824px → OK (29px 여유)
[s4] 내용 604px / 여유 824px → OK (220px 여유)
```

검사가 실제로 잡아낸 것들:
- s2 다이얼에서 "3 물보라" 라벨이 "1 포스터" 위에 얹힘
- s2 사각지대 캡션이 180° 눈금과 충돌
- s3 방위 칸이 26px 인데 "78°→−78°" 는 55px 라 제목과 겹침
- s3 내용이 50px 넘쳐 마지막 줄이 잘림
- 전 장 — `margin` 단축 속성이 부모의 `margin-inline: auto` 를 덮어써
  eyebrow/lede 만 왼쪽으로 밀려 있던 정렬 불일치

## 한글이 뭉개져 보일 때 — 대체 폰트

첫 PDF 가 "화면이 이상한데?" 소리를 들었습니다. 배경도 레이아웃도 멀쩡했고,
**한글이 전부 `GulimChe` 로 떨어져 있었습니다.**

`IBM Plex Mono` 에는 한글 글리프가 없습니다. 그런데 스택을 이렇게 적어 뒀습니다:

```css
--mono: "IBM Plex Mono", ui-monospace, SFMono-Regular, Menlo, monospace;
```

한글 대체가 없으니 브라우저가 시스템 기본 고정폭을 집는데, 윈도우에서는
`GulimChe` 입니다. 비트맵 느낌이라 뭉개지고, 거기에 라틴 대문자용으로 준
자간(`letter-spacing: .18em`)까지 그대로 걸려서 글자가 늘어져 보였습니다.
장표의 라벨·눈금·수식이 전부 이 스택을 쓰고 있었으니 화면 절반이 그렇게 됐습니다.

**고친 방법** — 라틴·숫자는 고정폭으로 두고 한글만 본문 서체로 떨어뜨립니다.
폰트 대체는 글리프 단위로 일어나므로 숫자의 고정폭 정렬은 그대로 유지됩니다.

```css
--mono: "IBM Plex Mono", "IBM Plex Sans KR", "Malgun Gothic", "Noto Sans KR",
        ui-monospace, monospace;
```

여기에 한글에 맞게 자간도 줄였습니다 (.18em → .07em 등).

📐 **PDF 의 내장 폰트 목록을 확인하면 바로 드러납니다.** 의도한 서체 말고
낯선 이름이 섞여 있으면 대체가 일어난 것입니다. 지금은 `GulimChe` 2개만
남아 있는데, `尺`·`ℝ` 처럼 어느 서체에도 없는 낱글자용이라 정상입니다.

## PDF 로 뽑을 때 주의

두 가지에 걸려서 빈 장만 나왔습니다. 다시 만들 때 같은 함정을 밟지 않도록 기록합니다.

1. **`@page` 를 mm 로 잡으면 안 됩니다.** `@page` 는 물리 치수를 CSS 픽셀로
   환산하는데(96px = 1in), 297×167mm 는 1122×631px 입니다. 이 덱은 1080px
   기준이라 내용이 페이지보다 커지고, 가운데 정렬된 내용이 페이지 밖으로
   넘쳐 빈 장만 남습니다. → `@page { size: 1920px 1080px }`
2. **`break-inside: avoid` 를 쓰면 안 됩니다.** 슬라이드 높이가 페이지 높이와
   같으면 크롬이 "안 들어간다"고 보고 계속 다음 장으로 밀어냅니다.
   또한 반올림으로 1~2px 만 넘쳐도 빈 장이 하나 더 생기므로
   `.slide { overflow: hidden }` 이 필요합니다.
