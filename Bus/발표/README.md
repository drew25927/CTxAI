## 제목을 이렇게 잡은 이유

원 제안서의 핵심기술 문장은 "연속 파라미터 블렌딩"만 담고 있는데, 그것만으로는
해자가 약합니다. 게임 오디오 미들웨어가 파라미터 블렌딩을 이미 하고 있고,
LLM 대사 생성도 흔합니다.

방어되는 지점은 **무요구(non-elicited)** 입니다. 감정 인식 연구는 거의 전부
*유도된* 반응을 씁니다 — 자극 영상을 보여주고 재거나, 연기한 표정 데이터셋을
쓰거나, 직접 묻습니다. 이 작품은 그걸 하면 안 되고(v1.1 §2 "관객이 해야 할 일은
벤치에 앉아 버스를 기다리는 것뿐"), 그 제약을 정면으로 받으면 문제가
**"자유로운 얼굴 → 감정 라벨"에서 "알려진 시각·방위의 자극 → 반응 커널"** 로
바뀝니다. 그래서 제목에 두 축을 다 넣었습니다.

상세는 `Bus/규격/프로브_하네스.md` §5.

## 레이아웃 검사

장표는 한 장이 화면 하나에 정확히 들어가야 하고, 요소가 겹치면 안 됩니다.
눈으로 보는 대신 재서 확인합니다.

```bash
# 감사기를 주입한 사본을 만들고 헤드리스로 측정
# (실제 절차는 아래 결과와 함께 세션 기록에 있음)
```

마지막 검사 결과 — **4장 전부 겹침 0건, 넘침 0건**:

```
[s1] 내용 771px / 여유 824px → OK (53px 여유)
[s2] 내용 704px / 여유 824px → OK (120px 여유)
[s3] 내용 795px / 여유 824px → OK (29px 여유)
[s4] 내용 604px / 여유 824px → OK (220px 여유)
```

검사가 실제로 잡아낸 것들:
- s2 다이얼에서 "3 물보라" 라벨이 "1 포스터" 위에 얹힘
- s2 사각지대 캡션이 180° 눈금과 충돌
- s3 방위 칸이 26px 인데 "78°→−78°" 는 55px 라 제목과 겹침
- s3 내용이 50px 넘쳐 마지막 줄이 잘림
- 전 장 — `margin` 단축 속성이 부모의 `margin-inline: auto` 를 덮어써
  eyebrow/lede 만 왼쪽으로 밀려 있던 정렬 불일치

## PDF 로 뽑을 때 주의

두 가지에 걸려서 빈 장만 나왔습니다. 다시 만들 때 같은 함정을 밟지 않도록 기록합니다.

1. **`@page` 를 mm 로 잡으면 안 됩니다.** `@page` 는 물리 치수를 CSS 픽셀로
   환산하는데(96px = 1in), 297×167mm 는 1122×631px 입니다. 이 덱은 1080px
   기준이라 내용이 페이지보다 커지고, 가운데 정렬된 내용이 페이지 밖으로
   넘쳐 빈 장만 남습니다. → `@page { size: 1920px 1080px }`
2. **`break-inside: avoid` 를 쓰면 안 됩니다.** 슬라이드 높이가 페이지 높이와
   같으면 크롬이 "안 들어간다"고 보고 계속 다음 장으로 밀어냅니다.
   또한 반올림으로 1~2px 만 넘쳐도 빈 장이 하나 더 생기므로
   `.slide { overflow: hidden }` 이 필요합니다.
