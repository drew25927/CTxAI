# 개발 착수 순서 — 프론트 · 백엔드 혼자 맡을 때

프론트와 백엔드를 혼자 다 맡으신다면, 순서가 특히 중요합니다. 예쁜 걸 먼저 만들지 말고 **가장 불확실한 연결부터** 뚫어야 합니다. 8/17 페어 테스트가 통과하느냐가 전부 이 연결에 걸려 있거든요.

## 추천 순서

### 1단계 — 화면 없이, 백엔드만 먼저 돌려보기

브라우저도 만들기 전에, 터미널에서 이것부터 확인하세요.

```
마이크로 녹음한 파일 하나
   → STT 서비스에 보내서 글자로
   → 그 글자를 LLM에 보내서 "공포/로맨스/코미디/판타지 점수를 JSON으로만 출력해" 프롬프트
   → 점수 4개가 콘솔에 뜨는가
```

여기서 확인할 것: STT가 한국어를 잘 받아쓰는가, LLM이 이상한 텍스트 안 섞고 JSON만 깔끔하게 뱉는가. 이게 안 되면 나머지는 다 헛수고입니다. 가장 위험한 부분이니 제일 먼저 검증하세요.

이 단계에서 STT랑 LLM API 키 발급, 요청/응답 형식 정하는 것까지 끝내면 됩니다.

### 2단계 — 브라우저에서 마이크 잡아서 서버로 보내기 (화면은 텍스트뿐)

3D 없이, 그냥 흰 화면에 버튼 하나. 누르면 녹음 → 서버로 전송 → 점수 돌아오면 화면에 숫자로 뜨기. 여기까지 되면 **핵심 파이프라인이 끝난 겁니다.** 나머지는 다 그 위에 얹는 장식입니다.

### 3단계 — 소리 섞기 (3D보다 먼저!)

소리 블렌딩이 제작 비용 대비 인상이 가장 강한 항목입니다. `GainNode` 4개 준비해두고 점수 비율대로 볼륨 조절하는 것부터 하세요. 3D 없이도 이것만으로 "오, 반응한다"는 느낌이 확 옵니다. 그리고 페어 테스트도 이 단계만으로 이미 돌릴 수 있어요.

### 4단계 — 최소 3D 씬 (상자 수준)

이제 PlayCanvas든 A-Frame이든 골라서 정류장 자리에 상자 하나, 조명 하나 놔두고, 점수에 따라 조명 색이 lerp되는 것 확인. 아트 에셋 기다릴 필요 없이 본인이 만든 회색 상자로 로직부터 검증하세요.

### 5단계 — 신뢰도 판단 + 되묻기 로직

1순위·2순위 점수 차이가 작으면 재질문 트리거. 이건 조건문 하나라 가볍게 끝납니다.

### 6단계 — 여기서 처음으로 페어 테스트

3D 디테일 없이 3~5단계까지만 있어도 테스트 가능합니다. "너 나랑 다른 걸 봤네"가 나오는지 지금 확인하세요. 통과 못 하면 대사·동행자 설계(사건의 층)를 다시 봐야 하고, 통과하면 이후는 다듬는 일만 남습니다.

## 왜 이 순서인가

3D나 아트를 먼저 손대고 싶은 마음이 들 텐데, 참으세요. **회색 상자 + 텍스트만으로 이미 "다른 이야기 봤다"가 나와야** 이 프로젝트가 성립합니다. 그게 안 되면 3D를 아무리 예쁘게 만들어도 소용없습니다. 반대로 이게 되면, 남은 3개월은 아트팀이 만든 에셋 갈아 끼우는 작업이라 마음이 훨씬 편해집니다.
