## 2. 🔲 먼저 결정할 것 — 조명 전환 방식

세부 개발 기획서에 "lightmap 2장을 셰이더로 섞는다"고 써 두었지만 **그건 확정이 아니라 한 가지 아이디어입니다.**

### 경로 A — 구운 조명(lightmap) 두 장을 섞는다

| | |
|---|---|
| 아트가 주실 것 | 프리셋 세트마다 **베이크된 lightmap 텍스처** + 두 번째 UV 채널이 정리된 씬 |
| 얻는 것 | 간접광, 부드러운 그라데이션, "구운 빛"의 질감 |
| 비용 | 프리셋 추가·수정마다 재베이크. UV 정리 필요. 개발 쪽에 셰이더 작업 이틀 |
| 위험 | 셰이더가 8/13에 안 되면 시연 항목 하나가 통째로 빕니다 |

### 경로 B — 실시간 조명과 안개만 쓴다

| | |
|---|---|
| 아트가 주실 것 | 프리셋마다 **숫자 표** — 조명 3개 이하의 색·강도·방향, ambient 색, 안개 색·농도 |
| 얻는 것 | 에디터에서 즉시 확인. 값만 고치면 새 프리셋. 보간이 공짜 |
| 비용 | 간접광 없음. 그림자 품질 낮음. 자칫 평평해 보일 수 있음 |
| 위험 | 거의 없음. 반나절 작업 |

### 경로 C — 프리셋마다 텍스처 세트를 갈아끼운다

부드러운 전환(크로스페이드)이 원리적으로 불가능하고 메모리가 터집니다. **탈락시키는 것을 권합니다.**

### 📐 제가 권하는 순서

**8월은 B, 9월에 A를 시도.**

B로 만든 숫자 표는 A로 갈 때 버려지지 않습니다 — A에서도 실시간 조명을 3개까지 함께 씁니다. 반대로 A부터 시작하면 8/13에 셰이더에서 막혔을 때 되돌릴 것이 없습니다.

## 3. [요청] 아트 — 필요 사항

### 3.1 공통 기술 규약

이 부분만은 제가 정해야 합니다. 안 맞으면 런타임에서 안 뜨거나 좌표가 어긋납니다.

| 항목 | 규약 |
|---|---|
| 파일 형식 | **GLB** (glTF 2.0 binary) |
| 축·단위 | **Y-up, 미터. 1 unit = 1m** |
| 씬 원점 | 벤치 착석 지점 바닥을 (0, 0, 0)으로 |
| 관객 눈높이 | **앉은 자세 Y = 1.15m** 기준으로 디테일 배분 (서 있는 시점 아님) |
| 피벗 | 각 오브젝트 피벗은 **바닥 접지면 중앙** |
| 텍스처 | PNG/JPG, **한 장 최대 2048×2048** |
| 애니메이션 | 클립 이름은 §3.4 표대로. **루트 모션 없음** (위치는 코드가 제어) |
| 파일명 | §3.5 명명 규칙 |

🔲 **폴리곤·드로우콜 예산은 8/17 Quest 3 실측 후 확정합니다.** 세부 개발 기획서에 적어 둔 "삼각형 30만"은 일반적인 브라우저 VR 기준값을 옮긴 것이고, 실제 여유는 그날 재 봐야 압니다. **그때까지는 상한을 신경 쓰지 말고 만들어 주세요.** 넘치면 제가 줄이는 방법을 찾아서 가져오겠습니다.

### 3.2 텍스처와 색 — 요청은 하나뿐입니다

**[요청] 조명이 색을 입힐 수 있는 상태로 주세요.**

같은 정류장이 네 장르로 읽혀야 하는데, 텍스처에 색이 이미 박혀 있으면 조명을 바꿔도 그 색이 비쳐 나옵니다. 그러면 장르가 갈리지 않습니다.

**"채도 15% 이하"는 제가 근거 없이 적은 숫자입니다.** 실제로 얼마까지 내려야 하는지는 여러분이 테스트해서 정해 주세요. 제가 필요한 건 숫자가 아니라 **"조명을 바꿨을 때 실제로 색이 바뀌는가"**입니다.

📐 판정 방법 제안: 소품 하나를 만들어 청록·호박 두 조명 아래에서 스크린샷을 찍어 보고, 두 장이 확실히 다른 인상이면 통과. 8/12 화이트박스 씬에서 30분이면 됩니다.

### 3.5 [요청] 파일 명명 규칙

코드가 파일명으로 찾습니다. 여기만 맞춰 주시면 나머지는 자유입니다.

```
장르 코드:  H(공포)  R(로맨스)  C(코미디)  F(판타지)

조명 프리셋      lp_{장르}/           예: lp_H/  lp_R/
조합 프리셋      lp_{장르}-{장르}/    예: lp_R-H/
3D 소품          prop_{이름}.glb
장르 소품        prop_{장르}.glb
NPC 애니메이션    att_{장르}.glb, att_neutral.glb
버스             bus_{장르}.glb
```

📐 이름을 다르게 두고 싶으시면 그렇게 하셔도 됩니다. **`manifest.json`에 매핑을 적으면 끝입니다.** 규칙을 강요하려는 게 아니라, 안 정해두면 제가 매번 물어봐야 하기 때문입니다.

### 3.6 [요청] ★ 노선도 표지판 — 이것만 구조 요구가 있습니다

관객이 말한 단어를 **정류장 이름 자리에 실시간으로 써 넣습니다.** ("친구앞", "졸업앞" 같은 식)

체험이 끝나고 두 사람이 "내 정류장 이름은 이거였는데?"라고 말하게 만드는 장치이고, 8/22 시연 필수 항목입니다.

**[요청]**
- 정류장 이름이 들어갈 자리를 **평면 사각형 하나로 분리**해 주세요 (별도 머티리얼)
- 그 면의 UV를 **0~1 전체로 펴 주세요**. 코드가 그 면 전체에 글자 이미지를 그립니다

📐 글자 크기·서체·색은 코드에서 정하지만, **어떻게 보여야 하는지는 알려 주세요.** 값만 맞추겠습니다.

## 4. [요청] 사운드 — 필요 사항

### 4.1 배경 소리 4종 — 중요한 전제 하나

**네 개가 동시에 재생되고, 볼륨만 바뀝니다.** 곡이 교체되는 게 아니라 겹쳐서 섞입니다. 그래서 일반적인 BGM과 요구 조건이 다릅니다.

| 항목 | 요청 |
|---|---|
| 개수 | 4 (공포·로맨스·코미디·판타지) |
| 길이 | **30초, 이음새 없는 루프** |
| 형식 | OGG Vorbis 또는 WAV (제가 변환) |
| 루프 | 샘플 단위로 딱 맞게. 앞뒤 여백 없이 |
| **음량 정규화** | **네 트랙의 integrated LUFS를 동일하게.** 게인 계산이 이 전제로 돌아갑니다 |
| **피크 헤드룸** | **−6 dBFS 이하.** 두 개가 겹쳐도 클리핑되지 않도록 |

### 4.2 [요청] 어떤 조합으로도 섞여야 합니다

이게 유일하게 까다로운 요구입니다.

**네 트랙 중 아무 두 개를 임의 비율로 겹쳐도 성립해야 합니다.** 총 12가지 조합이 실제로 관객에게 갑니다.

📐 그래서 제가 아는 한 이런 것들이 위험합니다 (음악은 제 영역이 아니니 판단은 맡깁니다):
- 뚜렷한 박자가 있는 트랙 두 개 → 겹치면 박자가 싸웁니다
- 명확한 조성이 있는 멜로디 두 개 → 조가 충돌합니다
- 같은 주파수 대역을 채우는 트랙들 → 겹치면 탁해집니다

**[질문]** 트랙마다 주로 쓸 주파수 대역을 나눠 두는 방식이 가능할까요? (예: 공포는 저역 중심, 판타지는 고역 중심) 그러면 겹쳐도 서로 자리를 비켜 줄 것 같은데, 실제로 그렇게 작업하는 게 자연스러운지 모르겠습니다.

## 5. [요청] 기획 · 대본 — 필요 사항

### 5.1 옆사람 대사

| 층 | 개수 | 줄 수 | 8/22 필요 |
|---|---|---|---|
| **사건 대사** — 옆사람이 나에게 원하는 것 | 4 | 배합당 3~4줄 | ⭕ **사건당 1줄이라도** |
| **문장 층** — 배합별 어법 | **16** | 배합당 3~4줄 (약 56줄) | 9~10월 |
| **콜백 템플릿** | 16 | 1줄 | P1 |

🔴 **문장 층은 12벌이 아니라 16벌입니다.** 컨셉 문서 8·10·13장에 12벌로 적혀 있는데, 4장 계산은 16입니다. 순수 배합 4개(사건=태도)도 고유한 대사가 필요합니다.

### 5.2 [요청] 제약 두 개

1. **사건 대사는 태도가 확정되기 전에 재생됩니다.** 그래서 사건 대사는 **태도 중립**이어야 합니다. "붙잡으려 한다"는 내용은 있어도, 그것을 *어떤 태도로* 하는지는 아직 정해지지 않은 상태입니다
2. **콜백 템플릿은 명사 자리를 `{noun}`으로** 비워 주세요

```
"...아직 그 {noun} 안 왔네요."
```

조사가 필요하면 이렇게 적어 주세요. 받침 유무는 코드가 처리합니다.

```
"{noun|이:가} 오기로 했었나요."   →  친구가 / 동생이
"{noun|은:는} 안 올 거예요."      →  친구는 / 동생은
```

### 5.3 [요청] 제출 형식 — 스프레드시트 한 장

문서보다 표가 편합니다. 이 열만 있으면 제가 `manifest.json`으로 변환합니다.

| 배합ID | 사건 | 태도 | 배합이름 | 순번 | 대사 | 최대길이(초) |
|---|---|---|---|---|---|---|
| R-H | 로맨스 | 공포 | 경계하는 그리움 | 1 | | 5 |
| R-H | 로맨스 | 공포 | 경계하는 그리움 | 2 | | 5 |
| R-H | 로맨스 | 공포 | 경계하는 그리움 | cb | ...아직 그 {noun} 안 왔네요. | 4 |
| R-H | 로맨스 | 공포 | 경계하는 그리움 | cb_fb | ...아직 안 오네요. | 4 |

📐 **음성 합성은 제가 합니다.** 텍스트만 주시면 됩니다. 후보를 LLM으로 대량 생성해서 골라내는 방식이 편하시면 생성까지 제가 해서 넘겨드릴 수도 있습니다 — **어느 쪽이 좋으신가요?** [질문]
