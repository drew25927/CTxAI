# 🧪 팀 셀프테스트 — `/interim`·`/film` 임계값 1차 보정

**작성:** 개발(세션) · 2026-09-14
**목적:** 20명 규모 정식 헤드셋 파일럿(11/7 발표 1주 전 목표) 전에, **팀원 2~3명만으로 지금 당장** 판정 임계값의 1차 값을 잡는다. 정식 파일럿은 이 1차 값이 맞는지 검증하는 용도로 미뤄도 된다 — 지금 임계값 보정 자체를 막고 있는 건 아니다.

**전제**: `/interim`·`/film` 둘 다 HUD에 등급/최종 배합 뒤에 숨은 **원시 숫자**가 이미 보이도록 만들어 뒀다. 이 문서는 그 숫자를 "무슨 값이 나와야 정상인지" 기준으로 읽는 법과, 읽은 값으로 실제 상수를 고치는 법을 정리한 것이다.

---

## 0. 준비물

- 노트북 + 웹캠·마이크 (헤드셋 있으면 더 좋음 — 없어도 드래그로 대부분 테스트 가능)
- 로컬 서버:
  ```bash
  cd ctxai-busstop-xr-audio-proto
  npm run dev        # /interim 등 일반 페이지
  npm run film       # /film 전용 (셸 환경변수 문제 우회)
  ```
- 셋이 짝을 지어 진행하면 좋다: **1명은 배우(정해진 반응 연기)**, **1명은 화면 보며 HUD 숫자 받아 적기**, 1명은 기록표 정리. 혼자 해도 되지만(자기가 반응하면서 동시에 화면을 못 보니) 끝나고 다시보기로 확인해야 한다.

각 배역은 **한 사람이 3번(공포형·호기심형·차분형) 다 해봐도 되고, 3명이 한 번씩 나눠 해도 된다.** 중요한 건 "의도한 반응을 했을 때 의도한 등급이 나오는가"다.

## 1. `/interim` (2분 20초) 테스트

### 1.1 타임라인 — 이 시각에 이 사건이 온다

| 시각 | 사건 | 신호 | 방위 |
|---|---|---|---|
| 0:15 | 판초 인물이 카페 쪽에서 걸어온다 (판정까지 계속) | **S1** 관심 | -35° (왼쪽) |
| 0:35 | 트럭이 물웅덩이를 튀긴다 | **S2** 놀람 | 정면(웹캠·마이크) |
| 0:55 | 바람에 포스터가 파닥인다 | **S3** 호기심 | +72° (오른쪽 뒤) |
| 1:13 | 고양이가 나타난다 | **S4** 정서 | 정면(웹캠·마이크) |
| 1:35 | 개구리가 운다(안 보임, 소리만) | **S5** 경계 | +135° (오른쪽 훨씬 뒤) |
| 1:55 | 판정 확정 | | |

### 1.2 배역별 연기 대본

**① 공포형** — 목표: 전부 H로 채점되는 것
- S1: 판초 인물 쪽을 거의 안 본다. 가끔(몇 초마다) 불안하게 힐끗거리기만.
- S2: 트럭이 튈 때 움찔하며 몸을 뒤로 젖힌다. 놀라서 "헉" 소리를 낸다.
- S3: 포스터 쪽은 잠깐 보고 만다(오래 안 봄).
- S4: 고양이가 무섭다는 표정을 짓는다(찡그림, 몸 사림).
- S5: 개구리 소리에 크게 놀라 **헤드셋이면 벌떡 일어선다.** (데스크톱 드래그로는 기립 신호 자체가 안 잡힌다 — 헤드셋으로만 확인 가능)

**② 호기심형** — 목표: 전부 C로 채점되는 것
- S1: 판초 인물을 힐끗 보고 만다(오래 안 봄, 대신 여러 번 재확인).
- S2: 트럭 튀는 거 보고 "어?"하고 짧게 웃거나 탄성.
- S3: 포스터 쪽으로 몸을 돌려 3초 넘게 유심히 읽는다.
- S4: 고양이 보고 웃는다(재밌어함).
- S5: 개구리 소리에 천천히 돌아보되 놀라지 않는다.

**③ 차분형** — 목표: 전부 R로 채점되는 것
- S1: 판초 인물을 3초 이상 담담하게 계속 본다.
- S2: 트럭 튀는 거 거의 반응 없음.
- S3: 포스터 쪽은 안 본다(관심 없음).
- S4: 고양이를 편하게 오래 지켜본다(웃지도 무서워하지도 않고).
- S5: 개구리 소리에 별 반응 없음.

### 1.3 기록표 — HUD에 뜨는 원시값을 그대로 적는다

각 사건이 끝나면 HUD의 "S_ 원시값" 줄이 잠깐 나타난다(스크린샷 추천). 아래 칸에 옮겨 적는다.

| 신호 | 지금 코드 기준값 | 공포형 실측 | 호기심형 실측 | 차분형 실측 | 의도한 등급이 나왔나? |
|---|---|---|---|---|---|
| S1 (look, retreat, recheck) | `lookSec≥3→A`, `recheck→B` | | | | |
| S2 (fear, amuse, startle, mic) | `startle>0.12→A`, `startle>0.05→B` | | | | |
| S3 (look, retreat, recheck) | `lookSec≥3→A` | | | | |
| S4 (fear, amuse, sustain, mic) | `amuse>0.5→D`, `fear>0.5→C` | | | | |
| S5 (retreat, 기립 여부) | 기립→A, `retreat>0→B` | | | | |

**⚠️ 알려진 설계 이슈 — 미리 알고 보면 덜 헷갈림**: 시뮬레이션(`npm run test`의 `sim-interim.mjs`)으로 미리 확인해보니, **S2에서 "단발로 크게 나는 소리"는 무섭게 지른 비명이든 놀라서 낸 탄성이든 마이크만으로는 구분이 안 되고, 지금 코드는 이걸 전부 "C(웃음·탄성)"로 채점**한다(`lib/interimGrader.js`의 `gradeS2FromWebcam` 맨 위 분기). 진짜 비명과 즐거운 탄성을 구분하려면 소리 크기(RMS) 말고 다른 신호(표정 등)가 같이 필요하다 — 이 셀프테스트에서 공포형이 트럭 사건에서 예상과 다르게 나오면 이게 원인일 수 있다. 급하면 마이크 분석 로직을 손보고, 아니면 "웹캠 표정이 더 강하면 표정을 우선한다" 같은 규칙을 기획과 상의해서 추가할 것.

### 1.4 값을 고치는 곳

- `lib/interimGrader.js` — 등급 경계값 (예: `if (startle > 0.12) return "A"`의 `0.12`)
- `lib/interimMic.js` — 소리 크기·반복 판단 기준
- `lib/standUpSense.js` — 기립 인정 기준(`RISE_M`, `RISE_WINDOW_SEC`)

고친 뒤에는 `npm test`를 다시 돌려서(특히 `test-interim.mjs`) 로직 자체가 안 깨졌는지 확인.

## 2. `/film` (5분) 테스트

타임라인·매핑표는 이미 `반응형_실시간_영화.md` §3·§5에 자세히 있다. 여기선 **HUD에서 뭘 읽으면 되는지**만 정리한다.

### 2.1 화면에서 읽는 법

사건이 끝나면 HUD 하단 "사건 목록"에 한 줄씩 쌓인다:
```
포스터   안 봄 · 속도0°/s · 후퇴0.00m
물보라   봤음 1.1s · 속도140°/s · 후퇴0.07m · 회복1.5s
```
- **속도**: `STARTLE_YAW_VEL`(기본 140°/s)과 비교 — 진짜 놀라서 홱 돌아볼 때 몇 °/s가 찍히는지 본다.
- **후퇴**: `RETREAT_M`(기본 0.07m)과 비교 — 헤드셋 위치가 뒤로 몇 m 밀리는지.
- **회복**: `SLOW_RECOVERY_SEC`(3.0초)·`FAST_RECOVERY_SEC`(1.5초)과 비교.
- 줄 위에 마우스를 올리면(또는 길게 누르면) 지금 코드에 들어간 임계값 4개가 툴팁으로 뜬다.

### 2.2 배역별 연기

`/interim`과 같은 세 배역(공포형·호기심형·차분형)으로, `반응형_실시간_영화.md` §5의 타임라인(포스터 0:06, 트럭+물보라 0:25~0:34, 카페 종+판초 인물 0:12~0:40, 개구리 0:37, 고양이 0:43~0:49, 고양이 비명 0:52) 각 사건마다 위 1.2절과 같은 방향으로 반응하면 된다.

### 2.3 값을 고치는 곳

- `lib/headPoseSense.js` 상단 상수 (`LOOK_TOLERANCE_DEG`, `STARTLE_YAW_VEL`, `RETREAT_M`, `SUSTAIN_SEC`, `SLOW_RECOVERY_SEC`, `FAST_RECOVERY_SEC`)

고친 뒤 `npm test`(`sim-headpose.mjs`)로 세 가상 관객이 여전히 의도한 장르로 갈리는지 재확인.

## 3. 참고 — 합성 시뮬레이션과의 관계

`npm test`를 돌리면 `sim-headpose.mjs`(`/film`)·`sim-interim.mjs`(`/interim`)가 자동으로 "겁많은/호기심많은/차분한" 가상 관객 셋을 합성 데이터로 흉내 내서, 지금 로직이 의도한 대로 갈리는지 사람 없이 확인해준다. **이건 로직 점검용이지 숫자 실측이 아니다** — 이 문서(팀 셀프테스트)가 실측을 대신한다. 둘 다 하는 게 이상적이다: 시뮬레이션으로 로직 버그를 먼저 잡고, 셀프테스트로 숫자를 1차로 잡고, 정식 파일럿으로 검증한다.
