## 4. 판정 로직이 사는 곳

- `lib/behaviorSense.js` — `/story-v2`·`/story-vr`가 쓰는 원래 판정. 웹캠 표정(MediaPipe FaceLandmarker 블렌드셰이프) 기반. **AND 조건을 average가 아니라 `Math.min()`(퍼지 AND)으로 합성** — 로맨스처럼 조용한 반응이 공포로 오판되던 버그를 이렇게 고쳤음(`판정_기준.md` 참고). 새 판정 로직을 짤 때 이 패턴(단순 평균 대신 조건별 min/max 합성)을 그대로 따르는 게 안전함.
- `lib/directionState.js` + `lib/directionMap.js` + `lib/headPoseSense.js` — `/film`의 연출 상태. 헤드 포즈가 1순위, 웹캠은 보조. §2의 표대로 매 프레임 갱신.

## 7. 지금까지 배운 것 (같은 실수 반복 방지)

### 기존 (v1.1 시절부터)
- Supabase Storage 새 형식 키(`sb_secret_...`)는 `apikey` 헤더도 같이 보내야 인증됨
- Supabase Storage 객체 키에 비-ASCII 금지 — `slotId+확장자`로 고정, 원본 파일명은 `records.json`에만
- `@react-three/fiber@8.18.0` + `@react-three/drei@9.122.0` + `three@0.183.0` 고정 (React 18/Next 14 호환)
- 조명 프리셋·할일·대사오디오·SFX는 파일이 아니라 Supabase에 저장됨 — 테스트로 올리면 팀 전체가 보는 실데이터가 됨
- `/api/assets` 슬롯은 **맨 처음 업로드만 자동 선택**됨, 이후는 `/api/assets/choose`를 명시 호출해야 함
- Vercel 서버리스 함수는 요청 바디 ~4.5MB 넘으면 413으로 거부 — 큰 오디오는 모노 다운믹스 등으로 우회

### `/film`·`/interim` 작업하며 새로 배운 것 (2026-09)
- **MediaPipe 판정에서 얼굴 랜드마크 하나(`CHIN`)를 기준점으로 쓰면 손으로 입을 가리는 것만으로 판정이 깨짐** — 대신 잘 안 가려지는 지점(`NOSE_BRIDGE` 등)을 쓰고, 프레임 간 이상치(순간적으로 튀는 값)를 버리는 로직을 넣을 것.
- **표정 블렌드셰이프 중 `jawOpen`은 웃음과 공포(입 벌림)에 둘 다 걸림** — 감정별 블렌드셰이프 세트를 겹치지 않게 고를 것. 겹치면 교차 억제항(한쪽이 강하면 다른 쪽 신호를 깎는 식)을 넣어야 함.
- **여러 조건의 AND를 평균(`(a+b+c)/3`)으로 구현하면 안 됨** — 신호 두 개만 강해도 세 번째가 0인데 평균이 높게 나와 오판함. `Math.min()`으로 진짜 AND를 구현할 것 (`lib/behaviorSense.js`가 실제 사례).
- **Vercel의 "자동 트래픽 완화"(`x-vercel-mitigated: deny`)는 Deployment Protection(SSO)과 다른, 플랫폼 레벨 차단**이라 프로젝트 설정만으로는 못 끔. §1의 우회(별칭 도메인 + `ssoProtection` API로 끄기)를 참고.
- **`npm run film`이 필요한 이유**: 이 개발 환경 셸에 비표준 `NODE_ENV`/`TURBOPACK`이 이미 잡혀 있어서, 그냥 `next dev`/`next build`를 돌리면 CSS 로드나 빌드가 깨짐. `env -u NODE_ENV -u TURBOPACK`으로 지운 뒤 실행하는 래퍼가 그래서 있음 — 다른 스크립트를 새로 추가할 때도 이 패턴을 따를 것.
- **헤드리스 크롬으로 `/film`을 관찰할 때 탭을 두 개 이상 띄우면 fps가 떨어져 프레임 dt가 0.1초로 클램프되고, 영화 시간 자체가 실제보다 느려짐** — 한 번에 탭 하나만.
- **`headPoseSense.beginEvent` 의 관찰 창(dur + tail 4초)이 판정 시각을 넘으면 그 신호는 판정에 영원히 안 들어간다** — `/interim` S1 이 그랬다(채점 1:59 vs 판정 1:55, 모든 세션의 `judge.breakdown` 에 S1 없음). 시뮬(`sim-interim.mjs`)이 +6초를 더 돌려 결함을 가리고 있었으니, 시뮬은 페이지와 같은 시각에서 끊을 것. 상세는 `Bus/인수인계_중간시연_interim.md` §7.
- Blender는 이 환경에 설치돼 있지 않다(§6) — 설치됐었다는 이전 기록과 달리 2026-09-14 확인 결과 없음. 3D 모델링/변환 작업을 코드로 해야 하면 설치부터 사용자와 상의할 것.
- 신뢰 안 되는 사이트에서 바이너리를 받아 실행하는 대신, 있는 도구(macOS 내장, 순수 JS/Python)로 우회하는 판단 기준 유지.
- **`OPENROUTER_API_KEY`(워크스페이스 "kocca")는 계정 전체 한도가 있고, 2026-09 기준 이미 $500 한도를 $500.72 써서 잔여 $0** — `/api/dialogue`·`/api/tts`·`/api/mood`·`/api/voicetone`·`scripts/gen-dialogue-pool.mjs` 전부 이 키를 씀. 키 상태는 `curl https://openrouter.ai/api/v1/auth/key -H "Authorization: Bearer $OPENROUTER_API_KEY"`로 바로 확인 가능(`limit`/`usage`/`limit_remaining` 필드). 한도 초과 시 TTS/LLM 호출이 전부 403 `Key limit exceeded`로 실패함 — 코드 버그 아님, [openrouter.ai/workspaces/kocca/keys](https://openrouter.ai/workspaces/kocca/keys)에서 한도를 올리거나 크레딧을 충전해야 풀림(계정/결제 설정이라 개발 세션이 대신 할 수 없음).
- **대사 풀(`manifest.json`) 텍스트를 고치면서 오디오(`.m4a`) 파일도 같이 지우는 스크립트를 돌릴 땐, 재합성이 API 문제로 실패할 가능성을 염두에 두고 먼저 `git status`로 되돌릴 수 있는 상태인지 확인할 것** — 실제로 로맨스 기울임 30개를 이 방식으로 교체하려다 OpenRouter 한도 초과로 막혀서, 지운 오디오 30개를 `git checkout`으로 전부 되돌린 적이 있음(다행히 커밋 전이라 데이터 손실 없었음).

## 10. 궤적 추종 연출 엔진 — 병합 뒤 상태 (2026-09-30 추가)

**한 줄 요약.** 작가가 트랙(공포·로맨스·블랙코미디)마다 긴장 곡선을 쓰면, 엔진이 도입부 사건에 대한 관객의 머리 움직임에서 관객별 반응 동역학 θ̂(이득·지연·회복·습관화)를 추정하고, 긴장 추정 x̂ 가 그 곡선을 따라가도록 관객마다 다른 자극(개구리·고양이 슬롯 변형, 판정 뒤 미세 자극, 대사 간격·BGM·가로등·안개·옆사람 거리·시선의 연속 조정)을 고른다. 팀의 장르 판정(헤드 포즈 판정, `/interim` 5신호 판정)은 그대로 두고 그 옆에 얹었다. 설계·수식은 `Bus/규격/반응형_실시간_영화.md` §8·§9, 심사·학회용 한 장 요약과 숫자의 단일 출처는 `Bus/규격/기술요약_궤적추종연출.md`·`기술요약_수치표.md`. 이 절은 "팀이 이어받으려면 무엇을 알아야 하는가" 만 적는다.

**전제(정직 표기).** 지금까지의 모든 수치·화면은 합성 관객(`lib/gazeSim.js`, 창작값) 또는 모델 관객(`lib/tensionSim.js`)으로 만들었다. 실제 사람 데이터는 없다. 따라서 결과는 "실제 관객에게 효과가 있다" 의 증거가 아니라 "관객 모델·긴장 추정·제어기가 설계대로 함께 동작한다" 의 증거다. 발표에서 숫자를 쓸 때는 이 문장을 같이 말할 것.

### 10.3 두 라우트와의 연결 지점 — 어디를 건드렸고 어디는 안 건드렸나

**팀 판정 로직은 한 줄도 바꾸지 않았다**: `lib/interimJudge.js` · `interimGrader.js` · `interimDrift.js` · `interimMic.js` · `standUpSense.js` · `behaviorSense.js` · `headPoseSense.js` · `directionState.js` · `directionMap.js`. 엔진은 판정 결과(장르)를 읽기만 하고 되돌려 쓰지 않는다.

**팀 파일에 덧붙인 곳**(`git diff origin/main --stat -- lib components app scripts` 로 확인 가능):
- `lib/interimTimeline.js` — S1 관찰 창 `S1_DUR`(94초, 채점 1:53). 예전 값은 판정 1:55 를 넘어 S1 이 판정에 한 번도 들어가지 않았다(`Bus/인수인계_중간시연_interim.md` §7). 팀 판정 규칙 자체는 그대로.
- `scripts/sim-interim.mjs` — 페이지와 같은 시각(`T.judge`)에서 끊는다(예전엔 +6초를 더 돌려 위 결함을 가렸다).
- `app/interim/page.js` — 팀 판정 옆에 관측 축 배선: `createEngagementSensor` 생성, 큐마다 `beginStimulus(probeFor(cue.name))`, 200ms 틱에서 `fitViewerModel`·`estimateTensionSeries`, `?monitor=1` 디렉터 모니터, 종료 카드 반응 지문, `?viewer=`·`?seed=` 합성 관객, `?kiosk=1`, 세션에 `engagement`·`control` 저장. 팀의 `if (cue.sense)` 분기·`judge()`·드리프트 호출은 그대로.
- `app/film/page.js` · `components/ReactiveStage.jsx`(`adjustRef` 오프셋) · `lib/filmTimeline.js` · `components/Bus.jsx`(문 개구부 텍스처) · `app/api/session/route.js`(목록에 route·viewer·speed) · `app/film/compare/page.js`(두 라우트 세션 비교).
- `app/film/film.module.css` — 모니터·HUD·종료 카드의 `word-break: keep-all` 과 질문·응답 줄 두 칸 배치, 합성 관객 배지 `.synthBadge`(B65·B110·B163). 팀 규칙은 지우지 않고 뒤에 덧붙였다.
- `lib/dialogueBeats.js` — +73줄: 자막 유지 창 `subtitleHoldSec`·`splitLead`·`nextPlayedBeat`, 대사를 밟지 않는 미세 자극 허용 창 `dialogueQuiet`·`quietState`(B118·B138). 팀의 `DIALOGUE_V2_BEATS`·`beatOf`·`gazeFor` 는 그대로.

- `scripts/test-interim.mjs` — +45줄: S1 관찰 창이 판정 2초 전에 닫히고 배속 1·4·6 에서 판정 시각에 S1 채점이 이미 나와 있는지(B59). 팀 단언은 그대로.

**두 라우트가 공유하는 것** — 이 파일을 고치면 두 화면이 같이 바뀐다: `engagementSense.js` · `viewerModel.js` · `tensionEstimate.js` · `viewerText.js` · `gazeSim.js` · `sessionCompare.js` · `DirectorMonitor.jsx`. 판정은 독립, 관측 축은 공유.

**`/interim` 에서 관측 축이 하는 일과 안 하는 일.** 다섯 사건은 `lib/interimProbes.js` 의 메타로 탐침이 되어 θ̂·x̂ 가 HUD·모니터·종료 카드에 뜨고, 같은 다섯 사건을 본 두 관객(공포형 θ̂ 이득 1.142 · 응답 5/5, 차분형 0.385 · 1/5)이 비교 화면에서 갈린다(수치표 C2). 판정 전에 자극을 바꾸지 않으므로 `/interim` 에는 "바꾼 연출" 이 없다 — 같은 자극에 다른 반응이 비교의 요점이다. 판정 뒤 연출을 관객별로 바꾸는 첫 레버(옆사람 착석 거리)는 §10.7 제안 상태다.

### 10.5 세션 JSON 에 남는 것 (`data/sessions/`, gitignore)

- 파일 이름: `/film` 은 `<시각>_<판정 장르>.json`, `/interim` 은 `<시각>_interim_<판정 장르>.json`. 본문에 `route`, `viewer{synthetic, profile, seed}`, `speed` 가 있다.
- 공통 `engagement` — `params`(임계값 잠정치) · `baseline` · `raw`(원시 자세 전량, 5분 약 2~3만 행) · `windows`(2초 창 잔움직임·집중도) · `stimuli`(사건별 반응 레코드: `responded`·`turned`·`atOnset`·`preTurn`·지연·봉우리·회복) · `summary`.
- 공통 `control.theta` — θ̂ `{g, L, tau, rho, n, nResp, levels, confidence}`. `levels` 가 1 이면 습관화 ρ 는 사전값 그대로다.
- `/film` `control` — `track` · `mode`(`full`) · `plan`(모니터 권고) · `slots{frog, cat}`(실제 결정: 변형 id·용량·사유·`actuation{sfx, volume, plays, gap}`) · `tracking` · `actuation{on, holdAfterMicro, ticks, micro, last}`. 이벤트(`events`)에 `control:slot`(슬롯 발동) · `control:micro`(미세 자극) · `control:actuate`(연속 조정 2초마다: `u`·`mode`·`offsets`·`applied`) 가 남고, OFF 세션에도 `control:actuate` 는 기록만 남아 ON/OFF 비교표를 세션 JSON 만으로 만들 수 있다.
- `/interim` — 팀 `judge{genre, totals, breakdown}`·`grades` 그대로 + `control{track, theta, sel(도달 점수), tension[](x̂ 시계열)}`.
- 비교 화면과 `scripts/export-engagement.mjs` 는 두 라우트 모두 `engagement` 에서 x̂ 를 같은 함수로 다시 계산한다. 세션 파일을 옮길 때는 `engagement` 를 빼지 말 것.

### 10.6 지금 말할 수 있는 수치와 한계 (출처 `Bus/규격/기술요약_수치표.md`)

- **시뮬(모델 관객 200명, 현실 조건, A3).** 제어 ON 은 OFF 대비 사건 봉우리의 관객 간 표준편차를 공포 10% · 로맨스 14% · 블랙코미디 8% 줄이고, 목표 곡선 대비 RMSE 를 7% · 7% · 10% 줄인다. 이상 조건 상한은 16% · 19% · 14%(A2). 편차가 주는 곳은 개구리 슬롯(49% 감소)이고 고양이 슬롯은 2% 뿐이다(A7, §10.7). 예전 문서·저널에 있는 "34~41%" 나 "26~34%" 는 초기 규약 시뮬(`npm run sim`)의 값이라 인용하지 않는다.
- **`/film` 1배속 ON/OFF 완주(B).** 제어기는 개구리를 한 번만 볼륨 0.5 로 울렸고(OFF 0.8, B2), 판정 뒤 ON 이 OFF 보다 대사 간격 +0.45초 · 옆사람 거리 +0.15m · BGM ×1.25(B3), 미세 자극 3회 vs 0회(B5).
- **한계(반드시 같이 말할 것).** ① 실제 사람 데이터 없음(E3). ② x̂ 는 사건 반응만 재므로 판정 뒤 장면의 연속 조정은 측정되지 않는 구간을 미는 개루프 보정이다 — 허용폭 안에 든 창 0/40(E1·A6). ③ 판정 전 두 슬롯은 응답 2개로 θ̂ 를 적합하고 고양이 슬롯은 관객을 거의 못 가른다(E5). ④ 합성 공포형은 x̂ 상한 1.0 에 자주 닿는다(E2). ⑤ 팀 판정은 경계 사례에서 흔들려 트랙 고정 없이는 같은 URL 도 판정이 바뀐다(D3). ⑥ 배속 완주의 판정은 쓰지 않는다(E6). ⑦ 합성 관객은 옆사람의 대사 중에 화자 쪽을 보므로(`?talk=0` 이면 보지 않음, B67) 미세 자극 반응 폭 같은 측정값이 이 설정에 따라 달라진다 — 같은 seed 2 완주에서 켬 vs 끔: 의도 일치율 0.305 vs 0.525, 미세 자극 2·3 반응 폭 107°/111° vs 75°/78°(B118 이전 측정). 실제 관객도 시작 자세에 따라 같은 교란을 받으므로 반응 폭을 관객 사이에서 비교할 때는 시작 방위를 함께 본다(B103).

### 10.7 팀에 제안 — 결정이 필요한 것 (우리는 팀 판정 로직을 바꾸지 않았다)

1. **판정 전 드리프트 선두가 공포형에게도 로맨스 → 블랙코미디로 보인다.** 1배속 `/interim` 공포형 합성 관객(최종 판정 공포 5점)의 관람 HUD 는 0:21~1:13 로맨스 선두, 1:13~1:55 블랙코미디 선두(67%)였고 판정 순간 공포 100% 로 뒤집혔다. 원인은 세션 `trajectory`·`grades` 로 확인했다: `app/interim/page.js` 는 신호 큐(0:15·0:35·0:55·1:13·1:35)마다 `judge(observations)` 의 장르를 드리프트에 넘기는데, (a) 채점된 신호가 하나도 없으면 팀 규칙④ "무반응 → 로맨스 디폴트" 가 선두가 되고, (b) 웹캠이 없는 회차(S2·S4 없음)에서 1:53 전에 채점되는 신호는 S3(포스터, 1:02) 하나뿐이라 그 등급 B(블랙코미디 1점)가 1:13 부터 선두가 되며, (c) 공포 점수를 가진 S1·S5 는 1:53·1:55 에 채점된다. 후보: 채점된 신호가 없을 때는 드리프트를 중립에 두기 / 큐 시각이 아니라 등급이 실제로 들어온 순간에 선두를 갱신하기 / S1 은 관찰 중 임시 등급을 주기. 스펙 §4 "선두가 바뀌면 방향도 바뀐다" 의 해석 문제라 팀이 정할 것. 이 정의를 두면 비교 화면의 선두 장르 띠와 시연자 설명이 함께 쉬워진다.
2. **`scripts/sim-interim.mjs` 가 비결정이다.** 공포형 힐끗 간격이 `Math.random()`(92행)이라 100회 중 2~6회 공포형이 블랙코미디로 판정되고, `npm test` 는 출력만 하고 단언이 없어 EXIT 0 이다. `lib/gazeSim.js` 의 결정적 난수(mulberry32, seed)로 바꾸면 회귀 테스트가 된다. 팀 스크립트라 동의 뒤 우리가 고칠 수 있다.
3. **`lib/headPoseSense.js` 의 `looked` 는 이미 그쪽을 보던 사건에서 첫 표본에 켜진다.** 정면만 보던 관객이 정면 8° 물보라를 "봤다"(S1·S3·S5 등급, /film 물보라 가중 1.0) 로 받는다. 우리 센서는 같은 문제를 `atOnset`(시작 순간 이미 보던 중)과 `turned`(돌렸는가)로 갈라 "보고만 있던 사건" 으로 따로 센다(`lib/engagementSense.js`). 팀 등급에도 같은 구분을 넣을지 결정.
4. **고양이 슬롯(0:43)은 현실 조건에서 관객을 거의 가르지 못한다(A7 −2%).** 결정 시각에 닫힌 응답이 포스터·물보라 둘뿐이라 θ̂ 가 사전값 쪽으로 수축되고, 보통형·둔감형이 같은 변형을 받는다. 후보: (a) 고양이 소리 변형만 개구리 레코드가 닫히는 0:44 뒤로 미루기(동선 변형은 등장 0:43 이라 불가) (b) 개구리 레코드 tail 을 줄여 0:42 전에 닫기 (c) 열린 레코드의 "지금까지 관측된 부분" 을 결정에 쓰기. 심사에서 "관객마다 다른 연출은 결국 개구리 하나인가" 가 나올 수 있으니 답을 정해 둘 것.
5. **판정 뒤 대사 장면의 헤드 포즈 창 증거가 공포형의 배합을 로맨스 쪽으로 민다.** 옆사람을 바라보는 장면에서는 "되돌아봄 적음·시선 이탈 적음" 이 로맨스 규칙에 걸리기 쉬워, 공포형 1배속 완주 4회 중 3회가 끝 배합 1위 로맨스였다. 종료 카드는 판정 때 배합을 주 문장으로 두어 모순은 없지만, "판정 뒤 흐름" 문장이 매번 로맨스로 나온다. 판정 뒤 창 증거의 가중(0.35)을 낮추거나 대사 장면에서 끄는 것을 검토.
6. **`/interim` 판정 뒤 옆사람 착석 거리**가 `lib/interimTimeline.js evalActors` 에 고정(`seatX = 0.35 + 0.9`)이다. `/film` 처럼 거리 인자를 받게 하면 관객별 연출의 첫 레버가 된다(덧붙이기 한 줄). 그 값을 정하는 순수 함수 `lib/interimAdapt.js`(θ̂·x̂ 봉우리·장르 → 거리·걸어오는 시간·인사까지 기다리는 시간·시선, 1배속 실측 공포형 1.35 m · 차분형은 응답 1/5 라 고정 0.9 m)는 2026-09-30 들어갔고(B170a), `evalActors` 인자·`page.js` 판정 순간 한 번 호출·세션 `control.adapt` 기록·비교 화면 "바꾼 연출" 줄은 아직이다(B170b).
